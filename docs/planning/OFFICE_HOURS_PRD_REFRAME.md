# Design: ST6 Weekly Commit Module PRD Reframe

## Problem Statement

The organization currently uses 15Five for weekly planning, but weekly work is not structurally connected to strategic execution. Employees can plan work without a required link to Rally Cry / Defining Objective / Supporting Outcome data, and managers cannot easily see whether team commitments support the right priorities until the week has already drifted.

The Weekly Commit module should replace the weekly Check-in / Priorities / Objectives-alignment slice of 15Five, not the full 15Five performance-management suite. Its core value is enforced strategic alignment: every weekly commitment maps to a Supporting Outcome in the RCDO hierarchy, moves through a complete weekly lifecycle, and becomes visible to managers through an alignment command center.

## Demand Evidence

Demand is prompt-derived. We do not have independent customer interviews, incident examples, or manager quotes. The PRD asserts the pain: 15Five weekly planning lacks a mandatory structural connection to strategic goals, and managers lack visibility into weekly work alignment.

The design should therefore make assumptions explicit rather than pretending the exact internal workflow is known.

## Status Quo

Working assumption: employees currently submit weekly plans in 15Five while strategic goals live outside that workflow or are only optionally linked through 15Five's Objectives model. This creates a visibility gap: the weekly planning artifact exists, but it does not reliably answer "which Supporting Outcome does this work advance?"

15Five research confirms the closest existing workflow is Check-ins with Priorities linked to Objectives. Useful mechanics to borrow:

- weekly check-in cadence
- small number of priorities per period
- priority completion and carry-forward
- objective linkage from weekly work
- manager review actions and team dashboards

The replacement should improve on 15Five by making RCDO linkage required and manager review accountable.

## Target User & Narrowest Wedge

Primary MVP framing: both IC and manager, but IC-first for data creation.

The IC weekly workspace creates the structured source of truth:

- create weekly commitments
- link each commitment to one Supporting Outcome
- assign prioritization / chess metadata
- lock the weekly plan
- reconcile planned vs. actual work
- carry unfinished work forward

The manager alignment command center realizes the business value:

- team plan completion visibility
- RCDO coverage by team member and outcome
- misaligned or needs-review commitments
- priority distribution and overload signals
- reconciliation and carry-forward risk
- review, comment, and flag actions

Narrowest credible wedge: a strategy-enforced weekly alignment system that combines IC commit entry with manager alignment visibility. It should not become a full 15Five clone.

## Constraints

- One-week build, accelerated by Codex and Claude Code.
- Must feel production-shaped even if some enterprise integrations are seeded or simplified.
- TypeScript strict mode, React 18, Vite 5, RTK Query, Flowbite React, Tailwind CSS.
- Java 21, Spring Boot 3.3, PostgreSQL 16.4, Spring Data JPA, Flyway.
- Auth0 OAuth2 JWT integration boundary.
- Outlook Graph API is a hard requirement.
- WC runs standalone for assessment but is structured as a Vite Module Federation remote.
- PA is assumed to mean Parent/Platform Application. PA owns global shell concerns such as top-level navigation, shell routing, monitoring, workspace orchestration, and production observability.
- Do not replicate PA's LogRocket, Loki, Yarn Workspaces, or Nx setup for the assessment.

## Premises

1. The product's core value is not weekly planning by itself; it is enforced strategic alignment. If a commit can exist without a Supporting Outcome, the product fails the PRD.
2. The baseline plan must lock before reconciliation, or planned-vs-actual becomes meaningless. Flexible editing all week erases the signal the product is supposed to measure.
3. Manager review must be built into the loop, not left as passive reporting. 15Five's value weakens when managers do not respond; this replacement should make review state visible and accountable.
4. Outlook Graph is required, but its MVP role is calendar touchpoints for weekly planning and reconciliation, not a full 1-on-1 replacement.
5. The source of truth for RCDO is unspecified. MVP should seed RCDO locally as read-only reference data while preserving an integration boundary for a future upstream PA strategy service, OKR platform, admin import, or CSV import.

## Approaches Considered

### Approach A: Strategy-Enforced 15Five Slice

Replace 15Five's weekly Check-in / Priorities / Objectives slice with a stricter weekly commit loop: IC commits, required Supporting Outcome link, chess metadata, plan lock, reconciliation, manager review dashboard, and Outlook planning/review events.

Pros:
- Strong fit to the PRD's explicit lifecycle.
- Keeps scope narrower than a full 15Five replacement.
- Makes RCDO linkage the differentiator.

Cons:
- Risks under-emphasizing manager visibility if the dashboard is treated as secondary.
- Requires careful lifecycle semantics.

### Approach B: Manager Alignment Command Center

Make the manager dashboard the centerpiece: team alignment, unlinked or misaligned work, review status, carry-forward risk, and RCDO coverage. IC entry exists mainly to feed the dashboard.

Pros:
- Directly addresses the stated manager visibility pain.
- Easier to demonstrate business value quickly.

Cons:
- Dashboard value depends on strong IC commit structure.
- If IC flow is too thin, manager data is weak.

### Approach C: Full 15Five Replacement Attempt

Build broad 15Five-like behavior across check-ins, priorities, objectives, reconciliation, manager actions, comments, analytics, Outlook, and adjacent performance-management workflows.

Pros:
- Most literal reading of "replace 15Five."
- Broad demo surface.

Cons:
- Too large for one week.
- Likely produces shallow features instead of a strong strategic alignment loop.
- Includes features outside the PRD's weekly planning scope.

## Recommended Approach

Use a merged version of A and B:

**Strategy-Enforced Weekly Alignment System**

ICs create RCDO-linked weekly commitments, and managers get a command-center view that exposes alignment, priority, reconciliation, and review risk across the team.

This approach follows the PRD's main statement: replace 15Five for weekly planning with a system that enforces connection to Rally Cries, Defining Objectives, and Outcomes through commit entry, prioritization, reconciliation, and manager review.

## Product Mechanics

### RCDO

RCDO means Rally Cry -> Defining Objective -> Supporting Outcome. This is inferred from the PRD and should be defined on first use. Weekly commits must link to a Supporting Outcome, not just a top-level goal.

### Chess Layer

"Chess layer" is not a standard 15Five term and appears to be internal PRD shorthand. Define it as strategic prioritization metadata:

- priority: P0 / P1 / P2
- work type: Strategic / Maintenance / Blocker / Unplanned
- confidence: High / Medium / Low
- alignment status: Aligned / Needs Review / Misaligned
- manager note: optional

Avoid game metaphors in the UI. The purpose is tradeoff visibility, not gamification.

### Lifecycle

Recommended lifecycle:

- DRAFT: IC creates and edits weekly commitments.
- LOCKED: IC locks/submits the weekly plan; the planned baseline is frozen.
- MANAGER_REVIEW: manager review status, not necessarily the IC plan state. Manager can comment, flag, and mark reviewed.
- RECONCILING: IC records actual outcome, completion, blockers, and carry-forward intent.
- RECONCILED: week is closed and becomes historical truth.
- CARRY_FORWARD: an outcome that creates or clones linked work into the next week, not a terminal state for the original record.

Controlled exceptions after lock:

- manager notes/comments
- alignment flag changes
- progress/status update
- blocker marking
- unplanned commit creation
- explicit unlock/amend action tracked in audit metadata

### Outlook Graph API

Outlook Graph API is MVP-required because it appears in the PRD. Keep the purpose narrow:

- create or sync weekly Commit Planning calendar event
- create or sync weekly Reconciliation / Review calendar event
- include a link back to the weekly plan or manager dashboard
- store Graph event IDs for update/cancel
- show integration status and graceful error handling

Defer full 1-on-1 agenda sync, Teams integration, recurring-event complexity beyond the weekly cadence, and broad calendar reading.

### Real-Time Visibility

MVP real-time means fresh on page load/refetch and RTK Query cache invalidation after mutations. True live updates via WebSockets, SSE, or push events are nice-to-have, not required for the one-week build.

## Out Of Scope

This module should not replace:

- 15Five engagement surveys
- Pulse as a mood/sentiment product
- High Fives / recognition
- full Best-Self Reviews
- 360 reviews
- performance ratings or calibration
- full 1-on-1 workspace
- manager coaching / Kona-like features
- HR analytics suite
- compensation or talent matrix
- HRIS provisioning

## Open Questions

- What does PA stand for? Current assumption: Parent/Platform Application.
- What existing PM remote pattern should WC follow?
- Where does production RCDO data live?
- Who can create or edit RCDO hierarchy data?
- What exact Auth0 claims identify employee, manager, team, and role?
- Should manager review be required before reconciliation closes?
- What should happen when a manager disagrees with an IC's alignment mapping?
- Are Outlook events created per employee, per manager, or both?
- How should unplanned work be represented after the plan locks?

## Success Criteria

- 100% of weekly commitments are linked to a Supporting Outcome.
- ICs can draft, lock, reconcile, and carry forward weekly commitments.
- Managers can see team alignment, review status, and reconciliation risk without opening each IC plan one by one.
- Planned vs. actual work is preserved by locking the weekly baseline.
- Carry-forward work is traceable from original commitment to next-week commitment.
- Outlook planning/reconciliation touchpoints are created or synced through Graph API.
- WC can run standalone for demo while preserving production remote boundaries.

## Distribution Plan

For assessment/demo, WC runs standalone as a client-side SPA backed by the Spring Boot API.

For production, WC is a Vite Module Federation remote loaded by the PA host app. The module should expose a single route/module entry point, use shared dependency declarations, avoid hardcoded shell navigation, and document the integration contract expected from PA.
