# /tdd brief — 5.7 `managerAlignmentNote` write (E6 PATCH) — manager-owned post-lock commitment note

Adds `managerAlignmentNote` to the E6 PATCH with **field-level authz**: it is **manager-of-owner-only** (the INVERSE of every other E6 field, which is IC-owner-only), writable only when the plan is `LOCKED`+, audited. The safety surfaces are the manager-capability authz (rule #3, §33) + the **field-level authz routing** (the same endpoint authorizes differently by field) + the **mixing rejection** (a single patch can't be both an IC edit and a manager note — different actors) + the §15 note-not-logged. **Own commit, no bundling.** For the standing impl (`0095db66`).

## Feature
Extend `PATCH /api/commitments/{id}` (E6) so the **active direct manager** of a commitment's plan owner can set `managerAlignmentNote` (manager-owned, `LOCKED`+ only, audited) — while every existing E6 field stays IC-owner-only. A patch providing `managerAlignmentNote` is a manager-only operation (rejects the IC-owner + a mix with IC fields). REQ-F-006/REQ-F-010.

- [ ] **Mixing rejection (Q2):** a patch providing `managerAlignmentNote` **AND** any IC field (title/description/SO/priority/workType/confidence/alignmentStatus/reconciliationOutcome/outcomeNote) → `400 VALIDATION_ERROR` (a single patch is one actor's — can't mix manager + IC fields).
