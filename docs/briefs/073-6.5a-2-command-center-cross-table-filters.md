## Acceptance criteria
- [ ] `CommandCenterFilters` gains `definingObjectiveId` (UUID), `priority` (`Priority`), `workType` (`WorkType`), `alignmentStatus` (`AlignmentStatus`) — all optional/nullable.
- [ ] `ManagerController` declares the 4 new `@RequestParam(required=false)` params (typed → a bad value → the 6.5a 400 `VALIDATION_ERROR` handler).
- [ ] **`definingObjectiveId`** filter: an EXISTS subquery over `manager_heatmap_cell` — a report is included iff a cell exists for `(manager_employee_id = <scope>, employee_id = s.employeeId, week_start_date = weekStart, defining_objective_id = :do)`. (Uses the heatmap grain; scoped consistently with the outer query — no IDOR widening.)
- [ ] **`priority`/`workType`/`alignmentStatus`** filters: each an EXISTS subquery over `weekly_commitment` — a report is included iff its plan has ≥1 commitment with that attribute: `EXISTS (wc WHERE wc.weekly_plan_id = s.weekly_plan_id AND wc.<attr> = :val)`, over the §4 `(priority)`/`(work_type)`/`(alignment_status)` indexes. (Scoped by `s.weekly_plan_id`, which the outer manager-scope already binds to the manager's report — no cross-manager leak.)
- [ ] All filters **combinable** (AND) with each other + the summary-level filters; all server-side (no client filtering).
- [ ] **N+1-free preserved:** the EXISTS subqueries are part of the SAME page + count queries (still a fixed 2 statements; the 6.5a Hibernate-statistics test stays green / is extended). No per-row lookup.
- [ ] **IDOR scope unchanged** — the `manager_employee_id` predicate is still the first, unconditional WHERE; the EXISTS subqueries only narrow (a report already in the manager's scope). Re-pin: a second manager's rows stay unreachable even with cross-table filters set.
- [ ] `weeklyPlanId`-null rows (a report with no plan shell yet): the commitment-EXISTS filters naturally exclude them (no plan → no commitment) — confirm that's the intended behavior (a report with no plan can't match a priority/workType/alignmentStatus filter).
- [ ] `./gradlew check` clean. **Ad-hoc security-reviewer** on the EXISTS scoping (confirm no IDOR widening) — orchestrator-invoked at Step 9.
