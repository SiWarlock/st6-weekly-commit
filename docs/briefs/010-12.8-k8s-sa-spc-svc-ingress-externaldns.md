## Things to flag at Step 2.5
1. **★Q-inject — how TF outputs reach the manifests.** The SA `role-arn`s, the ingress `certificate-arn`, and the SPC secret ARNs are TF outputs (known only post-apply). Manifests are static YAML. **My default vote:** manifests carry `${PLACEHOLDER}` tokens (e.g. `${IRSA_API_ROLE_ARN}`, `${ALB_CERT_ARN}`); the 12.11 CI step substitutes them from TF outputs (`envsubst` / `kubectl ... | envsubst`) before apply. kubeconform validates the structure with placeholders as strings. Confirm the mechanism (envsubst in CI) + that kubeconform passes with placeholders.
2. **★Q-SPC — SecretProviderClass shape + jmesPath ↔ 12.6 keys.** Per-SA SPC, ASCP `objects` referencing each permitted secret ARN with `jmesPath` extracting the 12.6 contract keys (db→`spring.datasource.{url,username,password}`; auth0→`jwt.issuer-uri`+`auth0.audience`; graph→tenant/client/secret) into mount files under `/mnt/secrets`, consumed via `spring.config.import` (Appendix D). **My default vote:** one SPC per SA, `objectName=<secret ARN>`, jmesPath per contract key → file; confirm the mount-file naming matches the `spring.config.import` path. This closes the 12.6↔12.8 boundary.
3. **★Q-extdns — external-dns config.** Image version (verify current via registry/Context7); `--policy=upsert-only` (safer — won't delete records it didn't create) vs `sync`; `--txt-registry` for ownership; `--domain-filter=${ROOT_DOMAIN}`. **My default vote:** upsert-only + txt registry + domain-filter. Confirm the image tag + policy.
4. **Q-extdns-irsa — role file home.** external-dns IRSA role in `iam_irsa.tf` (with the workload roles) vs a new file. **My default vote:** extend `iam_irsa.tf` (it's a workload IRSA role). Confirm.
5. **Q-split — keep one slice or split external-dns to 12.8b?** This slice is ~9 files. **My default vote:** keep as one cohesive "k8s deploy surface + DNS automation" slice; split to 12.8b only if it feels unwieldy when you spike it. Flag your call.
