## Root cause (priority item — confirmed by the orchestrator; the impl re-verifies)
`DemoIdentityProvider` keeps `personaRef.current = personaId` so the **next** request's applier sets the new `X-Demo-Employee-Id` — **but nothing invalidates the RTK Query cache.** `/api/me` + `/api/plans/current` (and the manager reads) are cached under fixed argless keys; a persona/header change doesn't change the cache key → **no refetch → the previous persona's data stays on screen.** A real correctness bug for any identity switch (manifests in the standalone demo; the remote gets identity from the host so it's standalone-scoped).
