# /tdd brief — wc-web styling foundation (shell + Cadence tokens + dark/light theming)

## Feature
Stand up the `apps/wc-web` React 18 / Vite 5 / TS-strict shell **themed from the Cadence design system at birth** — Cadence tokens → `tailwind.config` theme + a Flowbite-React custom theme (approach **A**, Tailwind/Flowbite-native), plus the dark-default + light-toggle `[data-theme]` mechanism with a persisted preference and a standalone-only theme toggle.

**F1 — Cadence token foundation + Tailwind/Flowbite-native bridge (ST.1, approach A):**
- [ ] All Cadence tokens from `colors_and_type.css` (neutral ramp, surfaces, ink, borders, brand, **six status tones** `neutral/info/success/warning/failure/accent` with `-fg/-bg/-border/-solid`, heatmap volume fill, type scale, spacing, radii, elevation/shadow, motion durations/easing) are expressed as **CSS custom properties** in one token stylesheet (`src/styles/theme.css`), with the **dark** values under `[data-theme="dark"]` (the default on the root element).
- [ ] `tailwind.config` `theme.extend` maps **semantic** scales to those vars — `colors: { surface, 'surface-raised', 'surface-sunken', ink: {primary,secondary,muted}, border, 'border-strong', brand: {...}, tone-{neutral,info,success,warning,failure,accent}-{fg,bg,border,solid} }`, plus `spacing`, `borderRadius`, `fontFamily`, `fontSize`, `boxShadow`, `transitionDuration`, `transitionTimingFunction` — every value referencing `var(--…)` (NOT hardcoded hex). Utilities like `bg-surface text-ink-primary border-border` resolve through the vars.
- [ ] A Flowbite-React **custom theme** object (`src/app/flowbiteTheme.ts`, applied via Flowbite's theme provider/`createTheme`) restyles the primitives this product uses (`Badge`, `Button`, `Table`, `Drawer`, `Modal`, `Tooltip`) to the Cadence skin via the same token utilities.
- [ ] **No bespoke `.wc-*` component CSS** is introduced (approach A). The ONE permitted CSS file is the **token-variable stylesheet** above — flag this as the **minimal forbidden-pattern exception** at Step 9 (see Cross-doc section); it is NOT component CSS, NOT CSS Modules, NOT styled-components.

**F2 — Dark/light theming mechanism (ST.2):**
- [ ] A `[data-theme="light"]` block in `theme.css` redefines the **foundation** vars (surfaces/ink/borders) + **AA-contrast-adjusted status tones**; the **brand stays indigo `#5E6AD2` in both themes** (do NOT revert light to `blue-600`). Light base derives from the spec's superseded light palette (`white`/`gray-50`/`gray-900`/`gray-200`) re-contrasted.
- [ ] `ThemeProvider` + `useThemePreference()` hook: initial theme = persisted `localStorage` → else `prefers-color-scheme` → else **dark**; sets `data-theme` on the root; persists on change; respects `prefers-reduced-motion`.
- [ ] A `ThemeToggle` control lives **only under `src/standalone/`** (the tree-shaken-from-remote convention, mirroring `PersonaSwitcher`); no remote-side module imports it. (The bundle-absence *proof* is deferred to Phase 9.3 with the federation remote build — here, assert correct placement + that no remote entry imports it.)
- [ ] Flipping the toggle flips every themed utility (a smoke test asserts a token's computed value differs between `data-theme="dark"` and `="light"`).

**Cross-cutting:**
- [ ] `/preflight` (frontend: `yarn nx lint wc-web && yarn nx typecheck wc-web && yarn nx test wc-web`) clean.
- [ ] `.env.example` documents `VITE_AUTH_MODE=demo|auth0` + `VITE_API_BASE_URL` (Appendix D.1) — stub only, no auth logic this slice.

## Things to flag at Step 2.5
1. **Dark/light strategy — CSS-vars vs Tailwind `dark:` variant.** Tailwind's `dark:` is single-axis; with dark-default + a `[data-theme]` toggle it's awkward. **My default vote: bind Cadence tokens into the Tailwind theme as `var(--…)` and flip them via `[data-theme]` — do NOT rely on Tailwind's `dark:` variant at all.** Every themed utility then resolves through vars; `[data-theme="light"]` is a pure addition. Confirm version-correct Tailwind theme + Flowbite-React `createTheme`/provider API via **Context7** before GREEN.
2. **Slice size / split point.** This bundles F0+F1+F2 as the foundation. **My default vote: one commit** (foundation is legitimately one logical unit; no safety invariant). If Step-2.5 review finds it too large, split into **two commits** — (F0+F1: themed shell) then (F2: dark/light mechanism). Implementer's call to flag.
3. **Light-palette derivation.** Light base from the spec's `white/gray-50/gray-900/gray-200` re-contrasted, indigo retained. **My default vote: yes** — author a complete light token block now (not a stub) so style-as-you-build works in both themes from here on. Tune status tones for AA on light surfaces.
4. **Flowbite-React version + theming API.** Flowbite-React's theming API differs across majors. **My default vote: pin the version 0.6 will carry and theme via the documented `createTheme`/`ThemeProvider` path (Context7-confirmed); a custom theme object, not per-instance `theme={}` props everywhere.**
