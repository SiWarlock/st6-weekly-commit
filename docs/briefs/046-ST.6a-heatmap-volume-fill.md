# /tdd brief — ST.6a: HeatmapGrid volume-fill (load encoding, decoupled from risk)

## Feature
Encode each heatmap cell's commitment **load/volume** via the neutral Cadence volume tokens (`bg-vol-light` / `bg-vol-normal` / `bg-vol-heavy`), keyed on `cell.commitmentCount`, **decoupled from the risk badges** (which stay the separate risk signal). Replaces the current uniform `bg-surface-raised` cell fill. First ST.6 sub-slice (manager-surface composition); render-only, Tailwind/token-native, `/tdd`.

## Acceptance criteria
- [ ] The `HeatmapGrid` cell button fill is keyed on `cell.commitmentCount` via the `bg-vol-*` tokens (replacing the uniform `bg-surface-raised` at `HeatmapGrid.tsx:140`): a small threshold→tone map — **default (confirm at 2.5):** `0 → neutral/none` (faint, e.g. keep `bg-surface-raised` or a transparent gap), `1 → bg-vol-light`, `2–3 → bg-vol-normal`, `≥4 → bg-vol-heavy`.
- [ ] **Volume is decoupled from risk:** the cell's `riskBadges[]` (via `RiskBadge`) render exactly as now, independent of the volume fill — a high-load cell with no risk gets a heavy fill + no badges; a low-load cell with risk gets a light fill + its badges.
- [ ] The cell **count text** (`data-cy="cell-commitmentCount"`) is unchanged — volume-fill is **additive** (load = the number AND the fill intensity), so load is never color-alone (REQ-S-005).
- [ ] **Token-native** — uses the already-wired `bg-vol-light/normal/heavy` utilities (`theme.css` `--vol-*` / `tailwind.config`); **no new token** unless the heavy-cell border is wanted (Cadence `--vol-heavy-border` — flag at 2.5; not wired yet).
- [ ] **Render-only — NO enum/Appendix-A change** (consumes `HeatmapCellDto.commitmentCount` + `riskBadges[]` verbatim). **No `.wc-*` CSS / no second stylesheet / no hex / no arbitrary `[…]` hatches** (forbidden #3). Both `[data-theme]` values render (the `--vol-*` tokens flip). `yarn` typecheck + lint + prettier + full Vitest pass.
