# /tdd brief — `wc-api` + `wc-sync-worker` base Spring Boot apps (BUNDLE: 0.4 + 0.5)

## Feature
Stand up two bootable Spring Boot 3.3 app skeletons — `WcApiApplication` (`:api`) and `WcSyncWorkerApplication` (`:worker`, a separate deployable) — each exposing actuator `health/liveness` + `health/readiness` for k8s probes, with profile resources wired (`local`/`demo`/`prod` + the api-only `flyway-migrate`), the `ORG_TIMEZONE` fail-safe, and both component-scanning the `:shared` `ClockConfig` — no domain endpoints, no SNS/SQS/Graph/auth/CORS.

## Things to flag at Step 2.5
1. **`ORG_TIMEZONE` fail-safe placement.** `OrgTimeConfig` (0.3) is a `:shared` POJO with a constructor-settable zone. My default vote: a small `@Configuration` in `:api` that reads `app.org.timezone`, does `ZoneId.of(...)` guarded (unset/blank/invalid ⇒ `America/Chicago` + `log.warn`), and produces/configures the `OrgTimeConfig` bean. Keep the fail-safe logic testable in isolation (a method or bean you can unit-test without a full context). Flag if you'd rather make `OrgTimeConfig` a `@ConfigurationProperties`. **Note:** the CronJob (D.4, later) needs the same fail-safe — design it reusable.
2. **Bundle confirmation.** 0.4+0.5 in one commit — both are Spring Boot app skeletons, same actuator/profile patterns, no domain/safety/cross-doc invariant. My default: **bundle** (per the speed directive). Each feature gets its own RED→2.5→GREEN; one Step-10 commit. Push back if either grows beyond a grokable unit.
3. **Worker HTTP for actuator probes.** k8s probes hit HTTP `health/{liveness,readiness}`, so the worker needs a servlet web server for the management endpoint even though it serves "no user request" (D.3). My default: **`spring-boot-starter-web` + `spring-boot-starter-actuator` on the worker**, no controllers — the web server exists only for probes. Flag if you'd prefer a management-port-only setup.
4. **JaCoCo × Spring Boot main classes.** `WcApiApplication`/`WcSyncWorkerApplication` `main()` is bootstrap-only; `@SpringBootTest` covers context load but not the `static main`. My default: **exclude the `*Application` classes from JaCoCo coverage** (standard) so the ≥80%/module gate stays honest about real code. Flag if you'd rather add a trivial `main()` invocation test.
5. **Liveness/readiness probe groups.** Spring Boot exposes `/actuator/health/{liveness,readiness}` when probes are enabled. My default: set `management.endpoint.health.probes.enabled=true` (+ minimal `show-details`) in base config so the sub-endpoints exist in all profiles (not just when a k8s env is auto-detected).
