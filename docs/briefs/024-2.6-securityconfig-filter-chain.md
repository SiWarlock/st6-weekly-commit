# /tdd brief — 2.6 SecurityConfig: filter chain, coarse gates, RFC-7807 denial rendering

> **Safety-touching integration slice.** This wires the **operational half** of rule #5 (the `DemoAuthFilter` must actually be IN the real-mode chain to reject the backdoor header in prod) and rule #3 (the resolved `UserPrincipal` must actually reach the `SecurityContext` so `DomainAuthorizationService` can authorize). A wiring bug here = a safety hole. **Standalone commit; ad-hoc `security-reviewer` at Step 7→8.**

## Feature
`SecurityConfig` wires the Phase-2 identity spine into the actual request path — the OAuth2 resource server (2.1/2.2) and the `DemoAuthFilter` (2.3) into one chain per mode, resolving every authenticated identity to a `UserPrincipal` via `PrincipalResolver` (2.4) — plus a `ProblemDetailsExceptionHandler` that renders authn/authz failures as RFC-7807 `application/problem+json` (the 2.5 denial exceptions included).

## Acceptance criteria (what "done" means)
- [ ] `SecurityConfig` wires **one chain per mode** (demo vs real, keyed on the canonical `demo-auth.enabled` — LESSONS §12): real = OAuth2 resource server (JWT) **+** `DemoAuthFilter` as backdoor-rejector; demo = `DemoAuthFilter` as authenticator, **no** JWT path. Bearer and demo are **never both** authenticating on one request.
- [ ] Every authenticated identity resolves to a **`UserPrincipal`** in the `SecurityContext` via `PrincipalResolver` — real mode: JWT → `Auth0ClaimMapper` → `Auth0Identity` → `resolve(Auth0Identity)`; demo mode: header UUID → `resolve(UUID)`. (So `DomainAuthorizationService` reads a real principal.)
- [ ] **Rule #5 operational half:** `DemoAuthFilter` **is registered in the real-mode `SecurityFilterChain`** (proven by test) so a demo header in prod is rejected `403`+audit; the chain includes `SecurityContextHolderFilter` so the `SecurityContext` is **cleared per request** (no thread-local bleed).
- [ ] **Custom `JwtDecoder` wins** over Boot's `OAuth2ResourceServerAutoConfiguration` `@ConditionalOnMissingBean` decoder (no-collision proof — register the autoconfig in the test runner).
- [ ] **Q-B inactive principal:** `PrincipalResolver.resolve(...)` returns `Optional.empty()` when the resolved `Employee.active == false` (zero extra DB hit — it already loads the row); the chain maps empty → **401 IDOR-safe**. Proven **end-to-end** (an inactive employee's valid identity → 401).
- [ ] Controllers carry **coarse gates only** (authenticated + role gate where applicable, e.g. manager-only surfaces); resource-ownership is delegated to `DomainAuthorizationService` (no `@PreAuthorize` carries ownership logic — asserted structurally where feasible).
- [ ] `actuator/health/liveness` + `/readiness` **public**; all `/api/**` require an authenticated principal (the preflight `OPTIONS` bypass is 2.7's, not here).
- [ ] `ProblemDetailsExceptionHandler` (NEW — the first `@RestControllerAdvice`) renders authn/authz failures as `application/problem+json` per B.21: **401** authn, **403** `AuthorizationDeniedException` (with `code` `IC_CANNOT_RESOLVE_DISPUTE`/`MANAGER_ROLE_REQUIRED`), **404** `ResourceNotFoundOrUnauthorizedException` (IDOR-safe), each with `safeMessage` + `traceId`, **never** a secret/stack/exception detail (RISK-016).
- [ ] `./gradlew check` green; ad-hoc `security-reviewer` run (rule #5 chain-firing, rule #3 no-bypass, rule #7 no leak).
