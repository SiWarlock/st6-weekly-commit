# /tdd brief — E14 manager heatmap + E15 cell drilldown (6.5b)

## Feature
The two manager **heatmap READ** endpoints completing the §9 read surface (after E13 command-center 6.5a/6.5a-2):
- **E14** `GET /api/manager/heatmap?weekStart=&definingObjectiveId=&supportingOutcomeId=` → `HeatmapResponseDto {weekStart, cells: HeatmapCellDto[]}` — the manager × direct-report × week × Defining-Objective grid. **NOT paginated** (bounded by reports × DOs). Coarse `authorizeTeamHeatmapAccess` + **IDOR-safe query-scoping** by `manager_employee_id = principal.employeeId()` (never a request value), mirroring E13.
- **E15** `GET /api/manager/heatmap/{cellId}/drilldown?page=&size=` → `HeatmapDrilldownDto {cellId, employeeId, definingObjectiveId, supportingOutcomes: DrilldownOutcomeGroup[]}` — the Supporting-Outcome breakdown for ONE report × DO cell; each SO group's commitments a **B.20 paginated envelope** of `WeeklyCommitmentDto` (`priority ASC, createdAt ASC`). **Own-cell-only** via the pre-existing `authorizeHeatmapCellAccess` → IDOR `404`.

## Acceptance criteria

### E14 — heatmap grid
- [ ] `HeatmapResponseDto` + `HeatmapCellDto` **records** (`api/manager/dto/`) mirror **B.12 verbatim** — the cell carries `cellId`, `managerEmployeeId`, `employeeId`, `employeeDisplayName`, `weekStartDate`, `definingObjectiveId`, `definingObjectiveTitle`, `commitmentCount`, the 7 §9 counts (`planned/unplanned/misaligned/needsReview/blocked/carryForward/unresolvedDispute`), `riskBadges: RiskBadge[]`; **never the entity** (audit-quartet/leak-tested).
- [ ] `GET /api/manager/heatmap` — coarse `authorizeTeamHeatmapAccess` (IC → `403 MANAGER_ROLE_REQUIRED`) FIRST, then **IDOR-scoped** to `manager_employee_id = principal.employeeId()` (never a request value); returns ALL the manager's active-direct-report cells for `weekStart`. **NOT paginated** (a plain `HeatmapResponseDto`, no envelope).
- [ ] `weekStart` required (absent → `400`, reusing the 6.5a handlers). Optional `definingObjectiveId` filter → cells for that DO (column-axis narrowing). `supportingOutcomeId` filter semantics → **Step-2.5 Q2**.
- [ ] `employeeDisplayName` + `definingObjectiveTitle` resolved join-side, **N+1-free** (REQ-NF-003) — a bounded query (not per-cell lookups); pin with a Hibernate-statistics test (fixed statement count regardless of cell count).
- [ ] New `ManagerProjectionMapper.toHeatmapCellDto(cell, employeeDisplayName, definingObjectiveTitle)`.

### E15 — cell drilldown
- [ ] `HeatmapDrilldownDto` + `DrilldownOutcomeGroup` **records** mirror B.12; each group = `{supportingOutcomeId, supportingOutcomeTitle, commitments: PageEnvelope<WeeklyCommitmentDto>}`.
- [ ] `GET /api/manager/heatmap/{cellId}/drilldown` — **own-cell** `authorizeHeatmapCellAccess(principal, cellId)` as the **FIRST** service statement (chokepoint, pinned by `verify(never()).…` on a denied authorize); a cell whose `manager_employee_id` ≠ principal → **IDOR `404` + denial audit**; a genuinely-missing `cellId` → `404` **no audit** (§25).
- [ ] Drilldown resolves the cell → `(employeeId, definingObjectiveId, weekStartDate)`; groups the report's that-week commitments by **Supporting Outcome** (the SOs under that DO); each group's commitments a **B.20 envelope** (`priority ASC, createdAt ASC`, F.5).
- [ ] **Affordance posture (load-bearing):** the drilldown's `WeeklyCommitmentDto`s use the **context-free `CommitmentMapper.toDto(c)`** → **empty `allowedActions`** (no RESPOND/RESOLVE/lifecycle affordances — dispute affordances are **E3/E4-only**, 5.5b; §35 confirmed E15 doesn't use `PlanMapper`). The nested dispute *object* (B.6) still resolves; only the *action* affordances are absent. Pin: assert `allowedActions` is empty on every drilldown commitment.
- [ ] **Bounded/paginated** — no unbounded trees (§14). page/size mapping across SO groups → **Step-2.5 Q3**.

### Both
- [ ] `./gradlew check` clean (from `apps/wc-api/`). **Ad-hoc security-reviewer** (orchestrator-invoked at Step 9): E15 own-cell IDOR (`404`-not-`403`, scope from the cell's stored `manager_employee_id` vs principal, never the request) + E14 manager-scoping (no widening) — the rule-#3 surface.

## Things to flag at Step 2.5
1. **E14 query shape** — a Criteria join query (mirror E13's N+1-free cross-join for `employeeDisplayName` + `definingObjectiveTitle`) **vs** a `findByManagerEmployeeIdAndWeekStartDate` finder + a batch name-resolve. My default vote: a **Criteria join query** (consistent with E13, N+1-free over the 2 joins) — but E14 is bounded + unpaginated, so a finder + batched name lookup is acceptable if it keeps a fixed statement count. Confirm.
2. **E14 `supportingOutcomeId` filter semantics** — the cell grain is **DO**, not SO. My default vote: resolve `supportingOutcomeId → its parent DO` (`SupportingOutcome.definingObjectiveId`) and filter cells to that DO (if both `definingObjectiveId` + `supportingOutcomeId` are given they must agree → else empty). Confirm — or is the intent a commitment-EXISTS narrowing (cells whose report has a commitment under that SO)? Cite REQ-F-020/021 if it disambiguates.
3. **E15 page/size across SO groups** — B.12 nests a B.20 envelope **per** `DrilldownOutcomeGroup`. My default vote: apply `page`/`size` to **each group's commitments independently** (same window per group). Confirm vs a single flat page across all groups (which the nested-envelope shape argues against).
4. **E15 grouping query** — resolve the report's that-week commitments joined `commitment → supporting_outcome → defining_objective`, filtered to the cell's DO, grouped by SO (one query + in-memory group, §22-style; or a per-SO finder). Confirm the cleanest shape + how an SO with zero commitments is handled (include empty group vs omit).
5. **Affordance posture** — confirm the context-free `CommitmentMapper.toDto(c)` (empty `allowedActions`) and that **no** caller threads a viewer context into the drilldown (no affordance leak; the §35 trace discipline).
6. **Commit split** — my default: **2 commits** (E14 list, then E15 drilldown) for bisectability + a clean E15 security-review target. Confirm, or propose 1 if you judge it cohesive. If E15 alone feels too large at Step 2.5, flag it and we split E15 to a 074-2 follow-on (re-sequencing, not a scope cut).
