## Things to flag at Step 2.5
1. **`Me` tag invalidation.** `MeDto.isManager` is relationship-driven and effectively per-session-static in MVP. **Default vote:** tag `Me`, **never invalidated** (like `RCDO`) — fetched once per session; no mutation lists it. Revisit only if a mid-session relationship change must reflect (out of MVP scope).
2. **Persona-aware `/` redirect target.** **Default vote:** `<Navigate replace>` — `isManager` → `/manager/command-center`, IC → `/weekly-commit`; pending → `LoadingState`, error → `ErrorState`. Alternative (a role-aware landing page) rejected — the routes already exist; a redirect is simplest + matches §7 "persona-aware default."
3. **Gating loading-state default.** **Default vote:** `useIsManager()` returns **false while `getMe` is pending/errored** (fail-closed — never flash a manager entry to an unconfirmed/IC actor, REQ-UX-005). Confirm.
4. **RcdoBrowser search.** **Default vote:** **client-side** filter over the fetched full tree (E2 returns the whole hierarchy "for browse/search"); no server search param. Confirm.
5. **SupportingOutcomePicker selection model.** **Default vote:** **controlled** (`value`/`onChange`, emits `supportingOutcomeId` + breadcrumb) so 9.6's form owns the value. Alternative (internal state + `onSelect`) rejected — the form needs the value in its own state for submit/validation.
6. **Remote now needs a host store (REQ-I-008/§7 boundary consequence).** Wiring `useCurrentUser` (an RTK Query hook) into the **eager** `AppRoutes` gating means the remote entry now requires a Redux `<Provider>` above it — standalone (`StandaloneShell`) + tests supply one; **remote mode relies on the host providing the shared Redux store singleton** (9.13 host contract). **Default vote:** wire it (this is the intended design), keep the `WeeklyCommitApp` `ready`-guard behavior, and **flag at Step 9 a 9.13 carry-forward** that the host-integration contract must document "host provides the Redux store + accessor before mount." Confirm you're comfortable the gating query belongs in the eager path (vs. deferring gating into a lazy boundary) — eager is correct for route registration.
