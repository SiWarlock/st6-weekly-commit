## Things to flag at Step 2.5
**ECR:**
1. **A-Q1 — image tag mutability.** Image tags = commit SHA (§13). Options: `IMMUTABLE` (a SHA tag can't be overwritten — safest for SHA tagging) vs `MUTABLE`. **My default vote: `IMMUTABLE`** — SHAs are unique per build; immutability prevents accidental tag reuse. Flag if a re-push workflow needs MUTABLE.
2. **A-Q2 — scan-on-push.** **My default vote: `scan_on_push = true`** (cheap vuln-scan win). Confirm.
3. **A-Q3 — lifecycle policy.** Optional hygiene: expire untagged images after N days / keep last K. **My default vote:** a minimal `aws_ecr_lifecycle_policy` (expire untagged > 14d) on both repos — cheap, prevents unbounded storage. Flag if you'd rather skip for MVP (thin).

**SNS/SQS:**
4. **B-Q1 — standard (not FIFO) queue + raw delivery.** Task pins both. **My default vote:** standard queue, `raw_message_delivery = true`. Confirm (FIFO would change the §10 transport semantics — not wanted).
5. **B-Q2 — `maxReceiveCount` value.** **My default vote: `5`** (a `sqs_max_receive_count` var defaulting to 5) — a message redrives to the DLQ after 5 failed receives. Flag if you want a different threshold.
6. **B-Q3 — encryption at rest.** Cheap best-practice: `sqs_managed_sse_enabled = true` (SSE-SQS, no KMS key mgmt) on queue + DLQ, and SNS SSE. **My default vote: SSE-SQS managed** (no KMS complexity, thin). This is transport-at-rest encryption — orthogonal to the §F.2 pointer-payload rule but good hygiene. Confirm/flag.
