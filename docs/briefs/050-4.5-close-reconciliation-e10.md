# /tdd brief — 4.5 `POST /api/plans/{id}/close-reconciliation` (E10) — RECONCILING → RECONCILED with completeness validation

> **Fifth Phase-4 slice — the reconciliation close gate.** The symmetric counterpart to 4.2 start-reconciliation: `RECONCILING → RECONCILED`, gated on a **completeness precondition** (every planned has an outcome AND every unplanned has both an outcome AND a Supporting-Outcome link). Reuses the §28/§30 transition shape. Safety-adjacent: the close gate + the **E6 per-state allow-list EXTENSION** (RECONCILING must now allow `supportingOutcomeId` edits for UNPLANNED commitments **only** — planned baseline stays frozen, rule #2) — **run the ad-hoc `security-reviewer` at Step 7→8** (the allow-list extension must not widen to planned-baseline SO edits). For the standing impl.

## Feature
`POST /api/plans/{id}/close-reconciliation` (E10, owning IC, plan `RECONCILING`, **no body**) transitions `RECONCILING → RECONCILED`, stamps `reconciled_at`, returns the updated `WeeklyPlanDto`. Rejected with `422 UNPLANNED_MISSING_LINK_AT_CLOSE` + `fieldErrors[]` unless every PLANNED commitment has a non-null `reconciliation_outcome` AND every UNPLANNED commitment has both a non-null `reconciliation_outcome` AND a non-null `supporting_outcome_id`. Plus the **E6 PATCH allow-list extension** so the IC can link an unplanned's SO before close (`supportingOutcomeId` editable in RECONCILING for UNPLANNED only).
