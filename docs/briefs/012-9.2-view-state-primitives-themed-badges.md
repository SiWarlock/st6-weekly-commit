## Acceptance criteria (what "done" means)
**View-state primitives (§7 view-state contract):**
- [ ] `LoadingState` — skeleton shimmer (`variant: 'table'|'cards'|'grid'|'inline'`) or centered spinner; ~150ms delay before showing; respects `prefers-reduced-motion` (static, no shimmer) per the ST tokens.
- [ ] `EmptyState` — icon + headline + one-line guidance + optional CTA.
- [ ] `ErrorState` — Flowbite `Alert` (failure tone) rendering the parsed `safeMessage` as **plain, Cypress-assertable text** (stable `data-cy`/role hook) + `traceId` (small mono) + optional `Retry`; **never `dangerouslySetInnerHTML`**; an XSS probe (`<img src=x onerror=alert(1)>`) renders **escaped** (REQ-S-005).
- [ ] `PartialState` — success content **plus** a dismissible `Alert` (warning tone) with `safeMessage` + `Retry`; never blocks (canonical case: plan loaded + Outlook sync `FAILED`).

**Themed status/risk atoms (ST.3 fold-in — Cadence §4.2):**
- [ ] `StatusBadge` renders `PlanState` (`DRAFT/LOCKED/RECONCILING/RECONCILED` + the `NOT_STARTED` manager shell) and `ReviewStatus` (`NOT_REVIEWED/REVIEWED_WITH_DISPUTES/REVIEWED` + derived `OVERDUE`) per the §4.2 tone+icon maps — each value its pinned tone (neutral/info/success/warning/failure) + Heroicon; lifecycle visually distinguished (REQ-UX-002).
- [ ] `RiskBadge` renders **only** the six `RiskBadge` values `{MISALIGNED, NEEDS_REVIEW, BLOCKED, CARRY_FORWARD, UNREVIEWED, OVERDUE_REVIEW}` (B.1) per §4.2 — `MISALIGNED/BLOCKED/OVERDUE_REVIEW`=failure, `NEEDS_REVIEW/CARRY_FORWARD`=warning, `UNREVIEWED`=neutral; **ring variant for the 2nd of each same-color pair** (`BLOCKED`, `CARRY_FORWARD`); icon-led, `size=xs`; renders nothing for an unknown/absent value (no throw).
- [ ] **Color is never the only signal** — every status/risk badge carries glyph **+** text label **+** color (legible in grayscale); asserted.

**Pagination + week label:**
- [ ] `Pagination` consumes the B.20 envelope (`page.{number,size,totalElements,totalPages}`); hidden when `totalPages ≤ 1`.
- [ ] `WeekRangeLabel` formats a Monday–Sunday range via `shared/lib/formatWeek.ts` (org-tz America/Chicago) — explicit "Jun 1–7, 2026" / relative / compact.

- [ ] `/preflight` clean; both `data-theme` values render the atoms.

## Things to flag at Step 2.5
1. **`statusTaxonomy.ts` shape.** **My default vote:** one typed map module (`Record<PlanState|ReviewStatus|RiskBadge|…, { tone, icon, label }>`) ported from Cadence `atoms.jsx`, consumed by all the atoms — keeps §4.2 the single source of visual truth (per `UI_UX_SPEC §5.5` wiring rule 4). Heroicons via `react-icons/hi` (the real package now, not the hand-authored kit glyphs).
2. **Skeleton vs spinner threshold + reduced-motion.** **My default vote:** `animate-pulse` skeleton for first load with the ~150ms delay; respect `prefers-reduced-motion` (drop the pulse) via the ST.2 mechanism (it's already declarative in `theme.css`) — confirm the atoms inherit it.
3. **`OVERDUE` derivation in `StatusBadge`.** **My default vote:** `StatusBadge` takes the source `ReviewStatus` + an optional `derivedOverdue` flag and renders the critical Overdue pill when set — **never** treat `OVERDUE` as a stored status (it's read-time derived per §3); the badge just renders what it's handed.
