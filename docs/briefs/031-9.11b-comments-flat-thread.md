## RED test outline (Step 2)
### A — `commentsApi`
1. **`getComments_reads_by_target_paginated_default_sort`** — `GET /api/comments?targetType=&targetId=&page=&size=`; returns a B.20 envelope; default sort `createdAt,asc` when unset (F.5); `providesTags` per-target. *Why:* §5 E20, B.20, F.5.
2. **`createComment_posts_body_and_invalidates_target_success_only`** — POST `{targetType,targetId,body}`; success invalidates the per-target comments tag → `getComments` refetches; error → no invalidation. *Why:* §5 E21, LESSONS §10.
3. **`comments_error_surfaces_safeMessage`** — a `404` (unseeable target) / `400` → `safeMessage` only, no detail/traceId leak (§6/§16).

### B — `CommentList`
4. **`renders_flat_comments_with_author_and_time`** — renders each `CommentDto` (author + body + createdAt) as a flat list; no nesting/indent logic.
5. **`renders_loading_empty_error_states_and_paginates`** — loading→`LoadingState`; zero content→`EmptyState`; error→`ErrorState`; page controls reflect the B.20 envelope (server-side paging).
6. **`xss_probe_body_renders_escaped`** — a body of `<img src=x onerror=alert(1)>` renders as escaped text (the literal string is in the DOM as text, no `<img>` element created); structural assert there is **no** `dangerouslySetInnerHTML` in the component. *Why:* REQ-S-005, §16, forbidden pattern #4.

### C — `CommentForm`
7. **`posts_nonempty_body_and_refetches`** — submit → `createComment({targetType,targetId,body})`; refetch on success (no optimistic); empty body is a UX-only block (server authoritative).
8. **`surfaces_server_safeMessage`** — a `400`/`404` renders the parsed `safeMessage`.

### D — Gating / wiring
9. **`comment_affordance_gated_on_COMMENT_allowedAction`** — the thread/affordance renders iff `can('COMMENT', target.allowedActions)`; absent → not rendered. Covers both a commitment target and a plan target.
10. **`comment_reachable_from_commitment_and_plan`** — pins Step-7.5: the commitment-level thread (CommitmentList) + plan-level thread (WeeklyPlanView) mount with their `targetType`/`targetId`.

## Things to flag at Step 2.5
1. **Comment mount points + a reusable `CommentThread`.** **My default vote:** a small `CommentThread({targetType, targetId, allowedActions})` composing `CommentList` + `CommentForm`, gated on `can('COMMENT', allowedActions)`; mount it (a) per commitment in `CommitmentList` (resolves the 9.7 placeholder) and (b) for the plan in `WeeklyPlanView`. Lazy/collapsible (mount the `getComments` query only when opened — avoids N queries per commitment row).
2. **Comments tag granularity.** **My default vote:** **per-target** tag `{type:'comments', id: \`${targetType}:${targetId}\`}` (a comment on one target invalidates only that thread, not all) — mirrors the per-id plans pattern (LESSONS §10/§13). `createComment` invalidates its target's tag only.
3. **Pagination UX.** **My default vote:** reuse `PageEnvelope<CommentDto>` + a simple pager (or "load more") with default sort `createdAt ASC` (F.5, chronological thread). Server-side paging, no client slicing.
4. **Flat rendering (rule).** **My default vote:** ignore `parentCommentId`/`depth` for layout (always null/0 in MVP, §11); render a flat chronological list. Do **not** build nesting/threading. Pin a test that a comment with (hypothetically) a non-null parent still renders flat — or simply assert no indent logic exists.
