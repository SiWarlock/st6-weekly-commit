# /tdd brief — 3.1 RCDO read service + `GET /api/rcdo` (RcdoTreeDto, read-only)

> First Phase-3 slice. A **read-only** endpoint — not safety-critical (the lock, 3.5, is the safety culmination later). It establishes the Phase-3 controller→service→DTO pattern on the 2.6 chain and the **SupportingOutcome lookup** that 3.4/3.5 commitment-linking depend on.

## Feature
`GET /api/rcdo` (E2) returns the full nested **RCDO hierarchy** (Rally Cry → Defining Objective → Supporting Outcome) as a `RcdoTreeDto` object wrapper, plus a `SupportingOutcome` lookup-by-id that backs commitment→SO linking.

## Acceptance criteria (what "done" means)
- [ ] `GET /api/rcdo` returns `RcdoTreeDto = { rallyCries: RallyCryNode[] }` — an **object wrapper, NOT a bare array** — with the full nested `RallyCryNode → DefiningObjectiveNode → SupportingOutcomeNode` tree (B.4 fields: `id`, `title`, `description?`, `active`, child arrays; `rallyCryId`/`definingObjectiveId` parent ids on children).
- [ ] All DTOs are **records, never entities** (forbidden-pattern #3); assert no entity-only field leaks.
- [ ] **Read-only for both IC and Manager** — authenticated, **org-wide read** (NOT a per-user-scoped resource → no `DomainAuthorizationService` per-resource call); unauthenticated → 401 (via 2.6). NO mutation endpoint registered anywhere (asserted structurally — REQ-D-003); `RcdoReadService` exposes only query methods.
- [ ] **Inactive RCDO nodes still serialize** with `active=false` (do NOT filter — the field is the contract; the demo seed is all-active).
- [ ] A **`SupportingOutcome` lookup-by-id** method (on `RcdoReadService`) resolves a valid SO (for 3.4/3.5 linking) and **rejects an unknown SO id** (not-found).
- [ ] `./gradlew check` (from `apps/wc-api/`) green; 100% on new types.

3. **`/api/rcdo` authorization.** Org-wide read → **authenticated-only, NO `DomainAuthorizationService` call** (RCDO isn't a per-user resource — like `/me`). Default: yes; confirm (don't add a no-op authz check).
