## Acceptance criteria (what "done" means)
- [ ] `RiskBadgeDeriver` derives the `List<RiskBadge>` for a cell from the SAME source state the counts use (the misaligned-union set, needs-review, blocked=`reconciliation_outcome=BLOCKED`, carry-forward, the review's `NOT_REVIEWED`/overdue) — **no behavior change** vs the current inline `riskBadges`; `ProjectionService` delegates to it (incremental == rebuild — the deriver is the single badge source for both paths, §17/6.7).
- [ ] Pinned mappings (RISK-014): `MISALIGNED` when the cell's misaligned-union count > 0; `NEEDS_REVIEW` when needs-review > 0; `BLOCKED` when blocked (`reconciliation_outcome=BLOCKED`) > 0; `CARRY_FORWARD` when carry-forward > 0; `UNREVIEWED` when the review is `NOT_REVIEWED`; `OVERDUE_REVIEW` when `is_review_overdue` (derived `NOT_REVIEWED ∧ now>reviewDueAt`, injectable `Clock`).
- [ ] **`NOT_REVIEWED` + past-due ⇒ `OVERDUE_REVIEW` co-emits with `UNREVIEWED`** (the R2 Marco case — the previously-untested overdue=true branch; RISK-014).
- [ ] No badge value outside the `RiskBadge` enum is ever emitted; a fully-`REVIEWED`/aligned/completed cell ⇒ empty `{}`.
- [ ] All badges derive deterministically (no conflict with state — RISK-014); the existing 6.2/6.3b ProjectionService tests stay green.
- [ ] `./gradlew check` clean from `apps/wc-api/`.
