## Feature
Stand up the **validating Terraform root-module skeleton** for `infra/terraform/`: S3 remote-state backend + DynamoDB lock, provider version pins with the dual AWS provider (default-region + aliased `us-east-1` for the CloudFront ACM cert), the root deploy variables (`ROOT_DOMAIN`, `region`, `rds_minor_version`, `env`), and the aggregation `outputs.tf`. Zero cloud resources yet — this slice produces a root that `terraform validate` + `fmt -check` + `tflint` pass cleanly, on top of which 12.2–12.11 build.

## Acceptance criteria (what "done" means)
- [ ] `infra/terraform/versions.tf` pins `required_version` (Terraform) **and** version constraints for the `aws`, `kubernetes`, `helm` providers; declares the **default `aws` provider** (`region = var.region`) **and** a second **aliased `aws.us_east_1`** provider fixed to `region = "us-east-1"` (for the CloudFront ACM cert per §12).
- [ ] `infra/terraform/backend.tf` declares an **S3 backend** (`backend "s3" {}` — partial config; bucket / key / region / DynamoDB lock table supplied at `init` via `-backend-config`, NOT hardcoded). State-bucket versioning + encryption are documented as required of the (HITL-created) bucket; this slice does not provision the bucket itself.
- [ ] `infra/terraform/variables.tf` declares: `ROOT_DOMAIN` (`string`, **required, no default** — OQ-001), `region` (`string`, default `"us-east-1"` — REQ-O-011), `rds_minor_version` (`string`, default = latest known 16.x minor ≥ `16.13`, with a `validation{}` block enforcing a `^16\.` prefix — RISK-011), `env` (`string`, default `"aws"`, `validation{}` enforcing `contains(["local","aws"], var.env)`).
- [ ] `infra/terraform/main.tf` is the root composition point (terraform/provider wiring lives in `versions.tf`; `main.tf` may carry the `terraform {}`/locals/root comments — no resources yet).
- [ ] `infra/terraform/outputs.tf` exists as the designated **aggregation file** with a structured comment block enumerating the eventual exports (RDS endpoint, ECR repo URLs, SNS topic ARN, SQS queue/DLQ URLs, S3 bucket name, CloudFront distribution id, hosted-zone id). **Only outputs whose backing resources exist are live** — at 12.1 that is zero, so `outputs.tf` ships with the comment block and no live `output` referencing a nonexistent resource (keeps `validate` green). Each later slice appends its own output here.
- [ ] **Verification (agent-side):** `terraform -chdir=infra/terraform init -backend=false` succeeds; `terraform -chdir=infra/terraform validate` passes; `terraform fmt -check -recursive` clean; `tflint` (terraform ruleset) clean.
- [ ] **HITL-deferred (documented, NOT run agent-side):** real `terraform init` against the S3 backend, `terraform plan` (provider/data-source calls hit AWS), state-lock acquisition against DynamoDB. Note the exact HITL `init -backend-config=...` invocation in the slice's session doc / a `docs/runbooks/` stub.
- [ ] Cross-doc invariant: **none** (IaC scaffolding; no Appendix A model).

## Verification outline (Step 2 substitute — infra has no RED test)
Author the `.tf` files, then prove the slice via:

1. **`terraform -chdir=infra/terraform init -backend=false`** — backend init skipped (no AWS); module + provider schema load succeeds.
   - Asserts: provider constraints resolve; the dual-provider (default + `us_east_1` alias) block parses.
   - Why: pins §12's "CloudFront cert in `us-east-1`" provider plumbing before any cert resource exists.
2. **`terraform -chdir=infra/terraform validate`** — config is internally consistent.
   - Asserts: no reference to an undeclared resource (this is why `outputs.tf` ships comment-only); variable validation blocks parse.
   - Why: the foundation must validate green so 12.2+ build on a known-good root.
3. **`terraform fmt -check -recursive`** — canonical formatting.
4. **`tflint`** (terraform ruleset) — lint clean (e.g. no unused declarations flagged in a way that breaks; deprecated-syntax checks).
5. **Negative checks (assert the guardrails bite):**
   - A `terraform validate` / `plan` run with `ROOT_DOMAIN` unset surfaces a **required-variable error** (no silent default) — demonstrable via `terraform validate` against a var-less invocation OR documented as the `plan`-time behavior (HITL).
   - An `rds_minor_version` like `"15.4"` fails the `^16\.` `validation{}` block.
   - An `env` like `"prod"` fails the `contains([...])` `validation{}` block.

## Things to flag at Step 2.5
Pre-loaded design questions with default votes. Take the defaults (fast path) or ping back with disagreement.

1. **`outputs.tf` strategy while backing resources don't exist yet.** Options: (a) author all exports now → `validate` FAILS (refs undeclared resources); (b) `outputs.tf` ships a structured comment block enumerating planned exports, with **zero live `output` blocks** at 12.1, and each resource slice appends its own output; (c) keep outputs inline in each resource `.tf` and skip a central `outputs.tf`. **My default vote: (b)** — honors C.6's single `outputs.tf` while keeping `validate` green at every slice boundary. (c) contradicts C.6; (a) breaks the foundation.
2. **`backend.tf` config completeness.** Options: (a) empty `backend "s3" {}` partial block, all params via `-backend-config` at HITL `init`; (b) hardcode bucket/table/region. **My default vote: (a)** — bucket/table names are environment-specific + the bucket is HITL-created; partial config is the standard pattern and keeps the repo deploy-target-agnostic. Document the real `init -backend-config=...` line for HITL.
3. **Provider version pins — exact constraints.** Confirm current stable majors before pinning (use **Context7 / the Terraform registry** at authoring time — don't pin from memory). **My default vote:** `required_version >= 1.9`, `aws ~> 5.x` (latest 5 major), `kubernetes ~> 2.x`, `helm ~> 2.x` — but **verify the current latest at author time** and pin to a real published constraint. Flag back if the registry shows a newer major (e.g. aws 6.x) you'd rather adopt.
4. **`rds_minor_version` default value.** The task says "latest available 16.x minor ≥ 16.13," but the *true* latest is region-dependent and only resolvable via `aws rds describe-db-engine-versions` (HITL). **My default vote:** default to `"16.13"` (the documented floor) with the `^16\.` validation block; note in the session doc that the real-latest resolution is HITL and changes in one place (RISK-011). Flag if you want a higher hardcoded floor.
5. **`kubernetes`/`helm` provider config at 12.1.** These providers can't authenticate without the EKS cluster (12.2). Options: (a) declare them in `required_providers` only, defer `provider {}` config blocks to 12.2/12.8; (b) add `provider {}` blocks now with cluster coordinates wired from (not-yet-existing) `eks.tf` data. **My default vote: (a)** — declare the constraint now so the lockfile is stable, but defer the configured `provider "kubernetes"`/`provider "helm"` blocks to the slice that creates the cluster (avoids referencing a nonexistent cluster + keeps `init -backend=false` clean).
6. **Add `.tflint.hcl` in this slice?** Options: (a) add a minimal `.tflint.hcl` enabling the **terraform ruleset only** (no plugin download → offline-friendly, `tflint` meaningful from slice 1); (b) defer tflint config to a later slice; (c) include the **AWS ruleset plugin** (deeper linting but needs `tflint --init` to download the plugin — network). **My default vote: (a)** — terraform-ruleset `.tflint.hcl` now; the AWS ruleset plugin is a HITL/optional add when we want deep AWS-resource linting (flag it as a Carry-forward item for whichever slice first benefits).
