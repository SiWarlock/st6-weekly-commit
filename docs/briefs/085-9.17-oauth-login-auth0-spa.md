# /tdd brief — OAuth login (Auth0 PKCE SPA) — the deployed-demo real-auth producer side (9.17)

## Feature
The **frontend OAuth login producer side** for the deployed real-backend demo: install `@auth0/auth0-react` and add a **standalone-only `Auth0IdentityProvider`** (parallel to `DemoIdentityProvider`) that runs the Auth0 PKCE SPA login, feeds `getAccessTokenSilently` into the **existing `setAccessTokenProvider` seam** (so the already-built `Authorization: Bearer` send "just works"), gates the app behind an unauthenticated **login screen**, processes the **`/callback`** redirect, swaps the app-bar **PersonaSwitcher → a "logged in as X" + logout** identity slot, and resets the RTK Query cache on identity change. The demo persona path stays intact for dev/MSW.

## Auth0 SDK API (Context7-verified, `@auth0/auth0-react`)
- `<Auth0Provider domain clientId authorizationParams={{ redirect_uri, audience, scope:'openid profile email' }} useRefreshTokens cacheLocation="localstorage" onRedirectCallback={(appState)=>navigate(appState?.returnTo ?? '/')}>` — **MUST mount inside `BrowserRouter`** so `onRedirectCallback` can use `useNavigate` (the `Auth0ProviderWithNavigate` pattern).
- `useAuth0()` → `{ isLoading, isAuthenticated, error, user, loginWithRedirect, logout, getAccessTokenSilently }`.
- `logout({ logoutParams: { returnTo: window.location.origin } })`.
- `getAccessTokenSilently()` — argless returns a JWT for the **provider-configured `audience`**. The `audience` is load-bearing: without it Auth0 returns an **opaque** userinfo token the resource-server can't validate.

## ✅ VERIFIED OAuth contract (backend-orch confirmed against `application.yml`/`application-prod.yml`)
All values from the real backend config — bake these into `auth0Config`/`.env.example` (the **values** are documented examples keyed to `<ROOT_DOMAIN>`; the live tenant values are injected at build per Appendix D.1 / §28):
- **`VITE_AUTH0_AUDIENCE` = `https://api.wc.<ROOT_DOMAIN>`** (== backend `auth0.audience`). **REQUIRED** in `authorizationParams.audience` (provider-level, so argless `getAccessTokenSilently()` returns the API JWT — else an opaque token the resource-server rejects).
- **Custom claim** the resource-server reads = `https://wc.<ROOT_DOMAIN>/employee_id` (the SPA does NOT set this — Auth0's post-login Action does; FYI only). There's also an optional `…/role` claim — **not needed** for login.
- **`VITE_AUTH0_DOMAIN` = the issuer tenant domain** (e.g. `https://<tenant>.<region>.auth0.com/`) — MUST be the SAME tenant the backend's `AUTH0_ISSUER_URI` points at (issuer ↔ SPA domain must match).
- **SPA origin = `https://wc.<ROOT_DOMAIN>`** (the backend prod CORS allow-list). This is the Auth0 SPA app's Allowed Callback / Logout / Web-Origins host (the `redirect_uri`/logout `returnTo` derive from `window.location.origin` at runtime — no hardcode; this just documents what the Auth0 tenant must allow + what CORS expects).

## Things to flag at Step 2.5
1. **Login-gate UX.** A branded in-app **LoginScreen** (manual gate: spinner → login screen → app) vs `withAuthenticationRequired` (immediate bounce to the Auth0 universal-login, no in-app screen). My default vote: **the branded LoginScreen** — the lead scoped "the unauthenticated login screen," and a branded screen demos better than an instant redirect. Flag if you'd rather bounce.
2. **`/callback` route vs `redirect_uri = origin`.** My default vote: **a dedicated `/callback` route** (`redirect_uri = <origin>/callback`). Rationale: `/` is already `RootRedirect` (persona-aware role landing) — landing the code-exchange on `/` races RootRedirect; a dedicated `/callback` isolates the exchange cleanly. **Implication (I'll handle at the round seal):** the Auth0 "Allowed Callback URLs" + the auth0-tenant-setup runbook must list `<origin>/callback` (not just the origin), AND the deployed CloudFront must serve `index.html` for `/callback` (SPA fallback — a 403/404→`/index.html` custom error response; standard SPA hosting, an infra note for the README + infra track). Alternative: `redirect_uri = origin` needs no extra route/runbook change but accepts the RootRedirect race — flag if you prefer it.
3. **StandaloneShell branch + bundle.** Default: **one shell, `VITE_AUTH_MODE`-gated** (not separate entries). The auth0 SDK statically imported in `Auth0IdentityProvider` ends up in the *standalone* bundle in BOTH modes — acceptable (REQ-I-008 constrains the **remote**, not the standalone demo build). Dynamic-import the auth0 provider only if the demo bundle size matters. Flag if you want the dynamic-import split now.
4. **AppBar identity slot.** Default: **AppBar takes the identity slot as a prop/children**, the shell injects PersonaSwitcher (demo) or Auth0IdentitySlot (auth0) — keeps AppBar mode-agnostic + testable. Flag if you'd rather AppBar read the mode internally.
5. **resetApiState key.** Default: key on **`user?.sub`** change, skip first mount (identity-scoped, matches §16). With `cacheLocation:'localstorage'`+`useRefreshTokens`, a returning user is restored without a reload → a stale cross-identity cache is possible, so the reset is real (not redundant). Flag if you'd rather reset on every `isAuthenticated` true-transition.
6. **`getAccessTokenSilently` failure (`login_required`/`consent_required`).** A silent-token failure (expired/revoked session) throws; `prepareHeaders` already normalizes it to a generic error (the existing error path renders). Default: **let it throw** (the existing path) for the demo; do NOT auto-`loginWithRedirect` from the seam (a redirect from inside a header builder is surprising). Flag if you want a re-auth-on-401 enhancement (a later slice).
