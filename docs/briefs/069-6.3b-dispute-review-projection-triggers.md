# /tdd brief — Dispute/mark-reviewed projection triggers + stale-cell deletion + RISK-003 (6.3b)

## Feature
Wire the **4 remaining §9 projection triggers** (dispute open/respond/resolve + mark-reviewed) through `ProjectionRefresher.recomputeForPlan(plan)`, add **stale heatmap-cell deletion** to the recompute path (so a Defining-Objective remap leaves no orphan cell), and prove **transactional atomicity** (RISK-003: a projection-upsert failure rolls back the whole domain mutation) + the §17 `lock→dispute→resolve→mark-reviewed` sequence end-to-end.

## Insertion points (verified)
- **`DisputeService.open`** (≈L84) — `plan` is already loaded in-scope (L90-93). Add `projectionRefresher.recomputeForPlan(plan)` after `reDeriveReviewStatus(...)` (≈L118), before/after the audit. (open increments `unresolvedDisputeCount` + may add the MISALIGNED-union/badge.)
- **`DisputeService.respond`** (≈L141) — currently loads the commitment **only** in the SO-revision branch. Load the commitment→plan (or just the plan via `dispute.getCommitmentId()`→commitment→`getWeeklyPlanId()`) and refresh at the end. **Its 5.4 docstring says "NO projection change" — that is now SUPERSEDED:** the rule-#2 SO-revision **remaps the commitment's Defining Objective**, so the heatmap cell grain shifts (old DO cell → stale; new DO cell → created). Update the docstring.
- **`DisputeService.resolve`** (≈L201) — the commitment is loaded (L212-215). Resolve plan via `commitment.getWeeklyPlanId()`; refresh after `reDeriveReviewStatus(...)` (≈L217). (resolve decrements `unresolvedDisputeCount`, may drop the MISALIGNED-union, flips `REVIEWED_WITH_DISPUTES→REVIEWED`.)
- **`ReviewService.markReviewed`** (≈L58) — `plan` is loaded in-scope (L63-66). Add the refresh after `reviews.save(review)` (≈L78). (markReviewed updates `review_status` + `is_review_overdue`.)

All four are already `@Transactional`, so the refresh joins the existing txn (RISK-003 atomicity holds).

## Acceptance criteria (what "done" means)
- [ ] All 4 triggers call `projectionRefresher.recomputeForPlan(plan)` inside their existing service-method transaction (never a controller); the projection row matches a fresh recompute after each (delta == recompute).
- [ ] **Stale heatmap-cell deletion:** `ProjectionService` (the recompute path, so ALL callers + the 6.7 rebuild get it) deletes any existing `manager_heatmap_cell` for `(manager, employee, week)` whose `defining_objective_id` is **not** in the freshly-computed DO set. Summary rows are unaffected (the grain is stable — only cells go stale).
- [ ] Dispute **respond** with an SO-revision that moves the commitment from DO-X to DO-Y leaves **no** DO-X cell (deleted) and a correct DO-Y cell.
- [ ] Opening then resolving a dispute returns `unresolved_dispute_count` (+ the MISALIGNED-union count/badge if MISALIGNED-flagged) to its prior value; mark-reviewed updates `review_status`/`is_review_overdue`.
- [ ] **RISK-003 transactional rollback:** injecting a projection-upsert failure during a trigger (e.g. dispute open) rolls back the **whole** mutation — no dispute row, no projection row, no audit — proving single-txn atomicity (no partial drift).
- [ ] **§17 integration:** a full `lock → open dispute(MISALIGNED) → resolve → mark-reviewed` sequence yields the §3-correct review status at each step and `is_review_overdue=false` after `REVIEWED_WITH_DISPUTES`, with the projection counts tracking each transition.
- [ ] `respond`'s "NO projection change" docstring corrected. `./gradlew check` clean from `apps/wc-api/`.

## Things to flag at Step 2.5
1. **Stale-cell deletion placement** — in `ProjectionService.upsertHeatmapCells` (delete existing cells whose DO ∉ new set, so every recompute caller + the rebuild get it uniformly) vs. a separate pass. Default: **in `upsertHeatmapCells`** (it already loads the `existing` cell map — add the delete there). Confirm it doesn't perturb the existing 6.2 ProjectionServiceTest expectations (those plans don't lose a DO, so no deletion fires).
2. **respond refresh — unconditional vs. only-on-SO-revision.** Default: **unconditional** (`respond` is a §9-listed trigger; simplest; the no-SO-revision case is a cheap no-op recompute that writes identical rows). Flag if you'd rather gate it on the SO-revision branch to save a recompute.
3. **RISK-003 failure injection mechanism** — a `@MockBean`/spy projection repo that throws on save within a real `@Transactional` Testcontainers test, vs. forcing a constraint violation. Default: **a throwing spy on the projection repo** inside the trigger's txn, asserting the domain row + projection row are both absent after the exception.
