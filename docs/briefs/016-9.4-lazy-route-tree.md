## Things to flag at Step 2.5
1. **Demo-header seam shape.** Replace the existing `DemoEmployeeIdProvider`/`getDemoEmployeeId` seam with a single `DemoAuthHeaderApplier` (`(headers: Headers) => void`) injected via `setDemoAuthHeaderApplier`, dispatched by `applyDemoAuthHeader(headers)` in `authAccessor.ts`; the standalone `DemoIdentityProvider` provides the applier (which holds the `X-Demo-Employee-Id` literal + reads `personaRef.current`). **My default vote: REPLACE** (single seam, header literal cleanly standalone-only, `getDemoEmployeeId`'s only consumer is `prepareHeaders`). Alternative: layer a new applier on top of the existing id-provider (keeps `getDemoEmployeeId`) — rejected as redundant surface.
2. **Placeholder route modules.** The five lazy routes need real modules to import; 9.5/9.7/9.9/9.10 deliver the real views. **My default vote:** minimal labeled placeholder components under `src/routes/pages/` (each a heading + "coming in 9.x"), replaced later — flagged as a carry-forward. Alternative (rejected): block 9.4 on 9.5+ existing. Confirm this file-list expansion.
3. **`isManager` gating source (9.4-before-9.5 wrinkle).** `meApi` (the real `MeDto.isManager`) is a 9.5 deliverable, but 9.4 owns the gating AC. **My default vote:** a thin `useIsManager()` seam in `routes/` backed by an injectable/placeholder value (fixture-driven in tests; default IC/false), swapped to read `meApi`'s `MeDto.isManager` in 9.5 (carry-forward). Keeps 9.4 testable without `meApi`. Alternative: defer gating to 9.5 — rejected (REQ-UX-005 is an explicit 9.4 AC).
4. **Failed-lazy-import boundary mechanism.** A rejected dynamic `import()` throws past `Suspense` and needs an Error Boundary to render `ErrorState`. **My default vote:** a minimal local class `RouteErrorBoundary` (no new dep) wrapping the `Suspense`. Alternative: react-router v6 `errorElement` (catches render/loader errors) — note it may not catch a lazy-import rejection the same way; or add `react-error-boundary` (rejected — avoid a new dep for one boundary).
5. **Commit structure.** REQ-I-008 is a safety mirror, so the boundary split gets its **own** commit. **My default vote: 2 commits** — (1) `refactor(wc-web): split demo-header attach into a standalone-only seam (REQ-I-008)`, (2) `feat(wc-web): lazy-loaded route tree mounted in WeeklyCommitApp (9.4)`. Implementer may argue for 1 atomic commit if they consider it one unit — surface the rationale.
