## Things to flag at Step 2.5
1. **REQ-I-008 proof form — static import-graph vs build-output grep.** **My default vote:** ship the **static import-graph assertion** as the reliable, fast guard (no module reachable from the remote entry imports `PersonaSwitcher`/`DemoIdentityProvider`/`ThemeToggle`), AND add a build-output grep **if** the federation build is wired enough to emit a `remoteEntry` cheaply. If the full federation build is heavy/flaky in CI, the static assertion is sufficient for this slice + note the build-output check for the 9.13 host-contract/Phase-11 E2E. Confirm `@originjs/vite-plugin-federation` version + config via **Context7**.
2. **Unknown-`VITE_AUTH_MODE` handling — throw vs normalized error vs dev-only.** **My default vote:** **throw a controlled error** at the `prepareHeaders` mode switch (`Unsupported VITE_AUTH_MODE`), since by 9.3 both real modes are wired — fail loud, no silent demo fall-through. No secret/raw detail in the message (safety #7).
3. **`VITE_API_BASE_URL` enforcement — fail-fast at module load vs at first request vs build-time.** **My default vote:** a single runtime guard in `baseApi.ts` that throws/loudly-warns if `VITE_API_BASE_URL` is unset in a non-test build (keep the absolute Vitest value via `test.env`); don't silently use `'/'` in the enforced path. Confirm whether a build-time check is cleaner via Context7/Vite docs.
4. **Host router/accessor injection shape.** **My default vote:** `WeeklyCommitApp` takes the host router context + `getAccessToken` via **props** (with a shared-singleton fallback) — the simplest testable contract; the exact PM-host pattern stays open (OQ-004, documented at 9.13). Keep it generic.
