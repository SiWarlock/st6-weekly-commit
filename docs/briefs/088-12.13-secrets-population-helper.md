# brief — Secrets-population helper: auth0 + graph HITL values (12.13)

> **Infra slice — NOT red-green TDD.** Verified via: `shellcheck` clean + a `--dry-run`/`--help` that prints the plan (secret names + key names only, NEVER values) + a no-op safety self-check. ## Feature
A guided **secrets-population helper** (`infra/scripts/populate-secrets.sh`) that writes the **operator-supplied** Auth0 + MS Graph credential VALUES into the **TF-created placeholder containers** (`aws_secretsmanager_secret_version` with `ignore_changes=[secret_string]`), run once after `terraform apply`. Reduces the irreducible secret-population HITL to a fill-in-the-blanks step (the operator brings the values from the Auth0 tenant + Entra app reg per runbook a; the helper does the `aws secretsmanager put-secret-value` calls with the correct key shapes). The `db` secret is **already TF-populated** (from RDS); `demo` is **no-op in prod** (demo-auth off) — the helper touches **only `auth0` + `graph`**.

  - **`wc/<env>/graph`**: `{ "GRAPH_TENANT_ID": …, "GRAPH_CLIENT_ID": …, "GRAPH_CLIENT_SECRET": … }` (the Entra app-registration creds for the Wave-2 worker).

  - **`wc/<env>/demo`**: placeholder, no-op in prod.

## Acceptance criteria
- [ ] NEW `infra/scripts/populate-secrets.sh` — sets the `auth0` + `graph` secret VALUES via `aws secretsmanager put-secret-value`, with the EXACT key shapes from `secrets.tf` (a drift between the script's JSON keys and `secrets.tf`/Appendix D would silently break the CSI mount → app boot).
- [ ] **Input via env vars OR interactive prompt** (see Step-2.5 Q1) — the client secret read with `read -s` (no echo); **NEVER** a committed/gitignored values file, never a CLI arg (shell history leak).
- [ ] **Rule #7 — structural, test-able by inspection:** the script NEVER echoes/logs a secret value (no `set -x` left on; no `echo $SECRET`); passes the secret JSON to the AWS CLI via **stdin/`file://` from a `mktemp` file `chmod 600` + `trap … EXIT` shred**, not an inline arg; emits only secret NAMES + key NAMES + the resulting version-id/ARN — never a value. A `# pragma: secrets — no value echo` banner + the shellcheck pass.
- [ ] **Targets only `auth0` + `graph`** — explicitly skips `db` (TF-owned) + `demo` (prod no-op); env-parameterized secret names `wc/${ENV}/{auth0,graph}`.
- [ ] **`--dry-run`** prints the plan (which secrets + which keys it would set, values redacted as `***`) and makes zero AWS calls. **`--help`** documents the required inputs (sourced from runbook a). Idempotent: re-running overwrites with a new secret version (safe).
- [ ] `shellcheck infra/scripts/populate-secrets.sh` clean; the `--dry-run` runs with no AWS creds.

## Things to flag at Step 2.5
1. **Input method:** (a) **env vars** (`AUTH0_ISSUER_URI`, `AUTH0_AUDIENCE`, `GRAPH_TENANT_ID`, …) read by the script — scriptable, CI-friendly, but the operator must `unset`/use a subshell to avoid env leak; (b) **interactive prompt** with `read -s` for the secret — safest for a human run, no env residue. My default vote: **support BOTH — env if set, else interactive prompt** (the secret always `read -s` if prompted). NEVER a values file or CLI arg.
2. **Audience/issuer source.** The `auth0.audience` is `https://api.wc.<ROOT_DOMAIN>` (deterministic from ROOT_DOMAIN) + the `issuer-uri` is the tenant URL (operator-supplied). My default: prompt for the issuer-uri; derive/default the audience from `ROOT_DOMAIN` with an override. Confirm.
3. **Post-set verification.** Read back the secret's `VersionId`/`ARN` (never the value) to confirm the write landed? My default: **yes** — echo the version-id only, as the success signal.
4. **Demo secret.** Skip entirely (prod no-op)? My default: **skip** — document that `demo` stays placeholder in prod (demo-auth off).
