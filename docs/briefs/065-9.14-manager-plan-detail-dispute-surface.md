# /tdd brief — 9.14 Manager plan-detail dispute surface (command-center review Drawer)

## Feature
Extend the command-center per-row review Drawer (`ManagerRowReview`) to render the direct-report's commitments through the already-`allowedActions`-gated `CommitmentList`, so the manager's `OPEN_DISPUTE` / `RESOLVE_DISPUTE` (+ `COMMENT`) controls — now emitted on the E4 plan read by backend 5.5b — have a home. This is the coherence-completing surface that makes the manager dispute workflow usable in-app (the IC plan view already hosts respond + display).

- **Task ID:** 9.14 (NEW manager task in the Phase-9 block — orchestrator stages it in `MVP_TASKS.md` at `/orchestrate-end`; lead-approved 2026-06-03, realizes a spec'd surface, not scope-creep).
- **Architecture sections it implements:** **E4 `GET /api/plans/{id}` scoped "Manager (direct-report)" → REQ-F-009 + REQ-S-001/002** (ARCHITECTURE §B.2 row E4); the dispute `allowedActions` emission (ARCH §B.1/§24 rows 371–373, realized by backend **5.5b `003394a`** on E3/E4 per viewing actor); §6 (IDOR-safe authz — manager direct-report scope, 404-not-403); §11 (server-authoritative gating).
- **Related context:** the manager dispute affordances went live with backend **5.5b (`003394a`)**: `OPEN_DISPUTE` on `WeeklyCommitmentDto.allowedActions` (direct manager, plan LOCKED+, no unresolved dispute), `RESOLVE_DISPUTE` on the nested `AlignmentDisputeDto.allowedActions` (direct manager, dispute OPEN|IC_RESPONDED) — both on E4. 9.11a (`743bdf9`) built the `{commitment}`-portable `DisputePanel` + respond/resolve forms (dormant until 5.5b — now active). `ManagerRowReview` (in `CommandCenter.tsx`) already lazily fetches the report's plan via `useGetPlanByIdQuery(planId)` (E4, LESSONS §13) for the review — `data.commitments` is already in hand.

## Acceptance criteria (what "done" means)
- [ ] **`ManagerRowReview` renders the report's commitments** via `<CommitmentList commitments={data.commitments} planState={data.state} planId={data.id} />` (no `onEdit` — the manager surface is read-only; `onEdit?` is optional). The E4 fetch already exists; this renders what it returns.
- [ ] **Manager dispute controls appear when authorized:** an undisputed commitment shows the `OPEN_DISPUTE` control (when `OPEN_DISPUTE ∈ c.allowedActions`); a disputed commitment shows the dispute display + the `RESOLVE_DISPUTE` control (when `RESOLVE_DISPUTE ∈ c.dispute.allowedActions`). All via the existing `DisputePanel` — **no re-derivation, gate on `allowedActions` (§11)**. The IC-only `RESPOND_DISPUTE` control does not appear for the manager (its allowedAction is absent).
- [ ] **Read-only correctness:** IC-authoring controls (edit/delete, reconciliation outcome form, carry-forward) do NOT render for the manager — they gate on IC `allowedActions`/DRAFT, absent here. Confirm via render assertions.
- [ ] **No-review case handled:** restructure `ManagerRowReview` so it renders the commitments even when `data.managerReview` is absent (today it early-returns "No review record yet."). A LOCKED+ plan always has a review (+ disputes only exist LOCKED+), but render commitments + the review section independently rather than gating commitments on the review.
- [ ] **IDOR-safe:** a `404` from `getPlanById` still renders `ErrorState(safeMessage)` (no crash, no existence leak, §6) — already handled; keep it.
- [ ] **MSW demo-data (standalone):** the **manager persona's** `getPlanById(reportPlanId)` returns a plan whose commitments emit `OPEN_DISPUTE` (undisputed, LOCKED+) and whose nested dispute emits `RESOLVE_DISPUTE`; the **IC persona's** plan read emits `RESPOND_DISPUTE` on its OPEN dispute (extends the 9.11a OPEN-dispute fixture) — so the real-browser QA can exercise both personas. (Static-coherent per persona; full mutation round-trip rides the Phase-13 mutable-`db` — see Step-2.5.)
- [ ] **Real-browser QA (gstack `/connect-chrome`, LESSONS §18):** the manager opens the command-center → expands a report's review Drawer → sees the commitments + the dispute controls; the open/resolve controls fire the correct E17/E19 calls; the IC persona sees the respond control. The end-to-end disputes proof across both personas.
- [ ] All unit tests pass; `yarn nx lint && typecheck && test wc-web` clean.
