# /tdd brief — ST.3: chess-layer atom skins (PriorityTag / WorkTypeTag / ConfidenceMeter / AlignmentChip)

## Feature
The four remaining Cadence chess-layer display atoms — `PriorityTag`, `WorkTypeTag`, `ConfidenceMeter`, `AlignmentChip` — built **Tailwind/token-native** (NOT the reference's `.wc-*` CSS), matching the Cadence visual spec, wired into `CommitmentList` so a commitment's chess fields render as skinned atoms. (First slice of the Phase-ST styling spine; `SyncStatusBadge` already shipped in 9.12, `StatusBadge`/`RiskBadge` in 9.2.)

## Use case + traceability
- **Task ID:** ST.3 (Phase ST — Cadence styling spine; first slice)
- **Spec source (binding visual):** `docs/design/cadence-design-system/ui_kits/weekly-commit/atoms.jsx` — the `WORKTYPE`/`ALIGNMENT` enum→tone+icon maps, `PriorityTag`/`ConfidenceMeter` structure; `colors_and_type.css` (tone tokens). **Architecture:** `ARCHITECTURE.md §4.2/§4.3` (enum→tone taxonomy), `§7` (render-only, Tailwind/Flowbite). **B.1 enums** (`Priority`/`WorkType`/`Confidence`/`AlignmentStatus`) — rendered verbatim.
- **Related context:** 9.2 (`StatusBadge`/`RiskBadge` + `statusTaxonomy.ts` — the pattern this extends), 9.12 (`SyncStatusBadge` + `SYNC_STATUS_TAXONOMY`, the 4th taxonomy), wc-web **LESSONS §3** (CSS-vars + `[data-theme]`, no `.wc-*` CSS), **§4** (Flowbite theming), **§7** (status-taxonomy single source of visual truth — glyph+text+color, unknown→nothing). The Cadence atoms.jsx + `components.css` are the **visual reference only** — do NOT port `.wc-*` classes (forbidden pattern #3).

## Acceptance criteria
- [ ] `commitment/PriorityTag.tsx` renders `Priority` (`P0`/`P1`/`P2`) as a tone-skinned tag (P0 = highest-urgency tone, descending) — Tailwind/token classes, the literal `P0`/`P1`/`P2` as text.
- [ ] `commitment/WorkTypeTag.tsx` renders `WorkType` per the Cadence `WORKTYPE` map — `STRATEGIC`→info/`HiSparkles`, `MAINTENANCE`→neutral/`HiCog`, `BLOCKER`→failure/`HiBan`, `UNPLANNED`→accent/`HiPlusCircle` — as icon+label (reuse the `Badge` primitive or a tag matching it).
- [ ] `commitment/ConfidenceMeter.tsx` renders `Confidence` (`HIGH`/`MEDIUM`/`LOW`) as a 3-segment meter (HIGH=3 filled, MEDIUM=2, LOW=1) + a capitalized label + a `title`; tone scales with level. Tailwind-native segments (no `.wc-conf` CSS).
- [ ] `commitment/AlignmentChip.tsx` renders `AlignmentStatus` per the Cadence `ALIGNMENT` map — `ALIGNED`→success, `NEEDS_REVIEW`→warning, `MISALIGNED`→failure — as a tone-dot + label.
- [ ] **Glyph+text+color + unknown→nothing** (LESSONS §7): each atom renders icon/indicator **and** text **and** tone (color is never the only signal — REQ-S/a11y); an unknown enum value renders nothing (no throw).
- [ ] Enum→tone+icon maps live in `shared/lib/statusTaxonomy.ts` (extend the §7 single-source pattern — `WORKTYPE_TAXONOMY`, `ALIGNMENT_TAXONOMY`; `Priority`/`Confidence` small maps) — **no inline re-mapping** at call sites.
- [ ] `commitment/CommitmentList.tsx` renders the chess atoms per commitment (priority + workType + confidence + alignment), so they're reachable (Step-7.5).
- [ ] **Render-only — NO enum/Appendix-A change** (the B.1 enums already exist in `dtos.ts`); cross-doc invariant: **none**. **No `.wc-*` CSS / no second stylesheet** (forbidden #3) — Tailwind/token classes + the existing `Badge` only.
- [ ] `yarn` typecheck + lint + prettier + full Vitest suite pass.

## Things to flag at Step 2.5
1. **Tailwind-native, NOT `.wc-*` (load-bearing).** The Cadence `atoms.jsx`/`components.css` are the **visual spec** (tones/icons/labels/structure) — implement them with Tailwind utility classes + the tone tokens + the existing `Badge` primitive, exactly as `StatusBadge`/`RiskBadge` did (9.2). **My default vote:** reuse `Badge` for WorkTypeTag (icon+label+tone, like RiskBadge); PriorityTag + AlignmentChip + ConfidenceMeter as small token-class components. **Do NOT** add `.wc-pri`/`.wc-worktype`/`.wc-conf`/`.wc-align` CSS or a second stylesheet (forbidden #3) — test #7 guards this.
2. **Taxonomy home.** **My default vote:** `WORKTYPE_TAXONOMY` + `ALIGNMENT_TAXONOMY` in `statusTaxonomy.ts` (the §7 single-source, alongside PLAN_STATE/REVIEW/RISK/SYNC); `Priority` + `Confidence` get small maps there too (or inline if trivial). One source of visual truth — no inline re-mapping.
3. **ConfidenceMeter structure.** **My default vote:** 3 segment elements, fill `HIGH=3/MEDIUM=2/LOW=1`, tone scales with level, + the capitalized label + `title="Confidence: …"`. Token-class fills, no `.wc-conf` CSS.
4. **PriorityTag tones.** atoms.jsx leaves P0/P1/P2 to CSS (`wc-pri p0/p1/p2`). **My default vote:** P0→failure/strong, P1→warning, P2→neutral (descending urgency) via tone tokens — confirm against `colors_and_type.css` if it pins specific priority hues; else this default.
