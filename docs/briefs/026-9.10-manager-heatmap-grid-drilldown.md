## RED test outline (Step 2)

### A — `managerApi.getHeatmap` (E14)
1. **`getHeatmap_passes_weekStart_and_optional_filters_not_paginated`** — `weekStart` required + optional `definingObjectiveId`/`supportingOutcomeId` serialize; **no `page`/`size`/`sort`** (E14 is not paginated); returns `{weekStart, cells}`. *Why:* §5 E14, B.12.

3. **`getHeatmap_surfaces_safeMessage_on_error`** — a `403`/`404` → `safeMessage` only (IDOR-safe).

### B — `managerApi.getHeatmapDrilldown` (E15)
4. **`getHeatmapDrilldown_requests_by_cellId_with_page_size`** — `GET /api/manager/heatmap/{cellId}/drilldown?page=&size=`; returns `HeatmapDrilldownDto` with `supportingOutcomes[]` each carrying a B.20 `commitments` envelope. *Why:* §5 E15, B.12, F.5.
5. **`getHeatmapDrilldown_404_surfaces_idor_safe_safeMessage`** — a `404` (cell not own) → `safeMessage`, no detail/existence leak (§6).

### C — `HeatmapGrid`
6. **`renders_cells_with_counts_and_enumerated_riskBadges`** — each cell shows the counts + `RiskBadge` for each value in `riskBadges[]` (enumerated, no opaque score); an unknown badge renders nothing (LESSONS §7). *Why:* REQ-UX-003, §9.
7. **`renders_loading_empty_error_states`** — loading→`LoadingState`; zero cells→`EmptyState`; error→`ErrorState(safeMessage)`.
8. **`selecting_a_cell_opens_drilldown`** — clicking a cell sets the selected `cellId` → mounts `HeatmapCellDrilldown` for that cell (skip-until-selected). Pins Step-7.5 E15 reach.

### D — `HeatmapCellDrilldown`

11. **`drilldown_paginates_commitments`** — page controls reflect the envelope `page`; next → re-query with the new `page` (server-side; no client slice; default sort `priority ASC, createdAt ASC` applied server-side per F.5).

## Things to flag at Step 2.5
1. **Tag = `manager`, NOT `heatmap` (parallel to 9.9 Q1).** The task text says "tagged `Heatmap`," but `app/tags.ts` has **no `heatmap` tag** — the `manager` tag co-covers both projections (§9). **My default vote:** `getHeatmap`/`getHeatmapDrilldown` `providesTags:['manager']`; they refetch on any `manager` invalidation (reconciliation/dispute/review/mark-reviewed mutations already do this). Orchestrator corrects the task text at `/orchestrate-end`.
2. **`RiskBadge` union home.** It's a B.1 enum but isn't in `dtos.ts` yet (the `RiskBadge` component takes a tolerant `value: string` + `RISK_TAXONOMY` lookup). **My default vote:** add `RiskBadge` to `dtos.ts` B.1 (the canonical home for B.1 enums — the 6 values `MISALIGNED|NEEDS_REVIEW|BLOCKED|CARRY_FORWARD|UNREVIEWED|OVERDUE_REVIEW`) so `HeatmapCellDto.riskBadges: RiskBadge[]` is typed; leave `RiskBadge.tsx` as `value: string` (tolerant display, LESSONS §7 unknown→nothing — `RiskBadge ⊆ string` so it still accepts the typed values). No taxonomy refactor.
3. **Drilldown trigger + lifecycle.** **My default vote:** a `selectedCellId` state (in `HeatmapGrid` or `HeatmapPage`) drives `getHeatmapDrilldown(cellId, {page,size})` **skip-until-selected**; the drilldown renders inline (panel/section) below or beside the grid; a `404` renders `ErrorState` (IDOR-safe). Mirrors the 9.9 lazy-fetch-on-expand pattern.
4. **Heatmap + drilldown query arg shapes.** **My default vote:** `getHeatmap` takes `{weekStart, definingObjectiveId?, supportingOutcomeId?}` (omit undefined); `getHeatmapDrilldown` takes `{cellId, page?, size?}` (defaults `page=0`, `size=25`). Reuse the generic `PageEnvelope<T>` from 9.9 for the drilldown `commitments`.
5. **Grid axes / rendering.** Report (row) × Defining-Objective (column) from the flat `cells[]` (each cell carries `employeeId`/`employeeDisplayName` + `definingObjectiveId`/`definingObjectiveTitle`). **My default vote:** pivot `cells[]` into a row(report)×col(DO) matrix client-side for display (pure transform, deterministic — testable); a missing (report,DO) cell renders empty. Visual polish (color intensity, layout) is ST.6 — deterministic tests pin the pivot + badge/count rendering, not pixels.
