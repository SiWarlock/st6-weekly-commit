## Acceptance criteria
- [ ] **`ProjectionRebuilder`** (a plain `@Component`, the logic) — `rebuild()`: **truncate** both projection tables (`manager_heatmap_cell` + `manager_plan_summary`), then iterate **all `WeeklyPlan`s** (`plans.findAll()`) calling `ProjectionRefresher.recomputeForPlan(plan)` (unmanaged plans no-op per §28; managed plans recompute from source). Returns a count (plans processed / cells+summaries written) for the log line.
- [ ] **`ProjectionRebuildRunner`** (a thin `@Component @ConditionalOnProperty(name="app.job", havingValue="rebuild-projections")` `ApplicationRunner`) — delegates to `ProjectionRebuilder.rebuild()`, logs the one-shot completion, holds no context (mirror `PlanShellGenerationRunner` exactly; `web-application-type=none` exit).
- [ ] **`rebuild == incremental` (the core proof):** seed a source state → build the projection from source (the incremental truth) → **corrupt/drift it** (mutate a count, delete a cell, inject an orphan cell for a DO the source no longer produces) → run `rebuild()` → assert the projection is **back to the correct-from-source state** (counts + badges correct, the orphan cell pruned, no missing cell). This proves the rebuild reconstructs from source = the incremental result (REQ-D-013).
- [ ] **Idempotency:** `rebuild()` run twice → identical projection (truncate+recompute is naturally idempotent; no duplicate rows — the `unique(manager,employee,week[,DO])` holds).
- [ ] **SYSTEM audit (§23):** one SYSTEM null-actor `audit_event` per run (safe metadata — e.g. plans-processed count; **no resource text**, §15), even on 0 plans. Reuse `AuditService.record(...)` + the injected `Clock` + the org-tz fail-safe.
- [ ] **No-active-manager / no-review plans** are skipped (the §28 `recomputeForPlan` no-op) — a rebuilt projection contains rows ONLY for managed+reviewed plans (same as incremental).
- [ ] `./gradlew check` clean. **No security-reviewer** — this is a SYSTEM batch job, not a rule-#3/IDOR surface (per handoff 011's reviewer list: 6.5b/6.6/073 only). The SYSTEM-context exemption is the pre-existing sealed-marker (§17/LESSONS §23), not re-authored here.

## RED test outline (Step 2)
1. **`rebuild_reconstructsProjectionFromSource_equalsIncremental`** — seed a managed plan with commitments/dispute/review → `recomputeForPlan` builds the correct projection (snapshot it) → corrupt it (change a count, delete a cell) → `rebuild()` → assert the projection == the snapshot (counts/badges/cells row-for-row).
2. **`rebuild_prunesOrphanCells`** — inject an orphan `manager_heatmap_cell` (a DO the source no longer produces) → `rebuild()` → the orphan is gone (truncate+recompute leaves only source-produced cells).
3. **`rebuild_isIdempotent`** — `rebuild()` twice → identical row set, no duplicates (the uniques hold).
4. **`rebuild_skipsUnmanagedAndUnreviewedPlans`** — a plan with no active manager (or no review) → no projection rows after rebuild (the §28 skip).
5. **`rebuild_writesOneSystemAuditRow`** — one `AUTHORIZATION`-free SYSTEM audit row per run (null actor, safe metadata, no resource text), even with 0 plans.
6. **`rebuildRunner_gatedOnAppJobProperty`** — `ApplicationContextRunner`: the runner bean is present ONLY with `app.job=rebuild-projections`, absent otherwise (mirror the PlanShellGeneration gating test; don't let it auto-fire).
