## Feature
`POST /api/plans/{id}/lock` (E8, owning IC, plan `DRAFT`) validates the lock preconditions and, in **one `@Version`-guarded transaction**, transitions the plan `DRAFT→LOCKED`, freezes the planned baseline, creates the manager review (with a weekday-only SLA `reviewDueAt`), upserts the manager projections, writes the audit + the `IC_PLANNING` sync record + the per-manager/week `MANAGER_REVIEW_BLOCK`, then publishes a pointer to SNS **after** the core commit — with Outlook strictly non-blocking. Returns the updated `WeeklyPlanDto` (B.5).

## Acceptance criteria (what "done" means)
- [ ] `POST /api/plans/{id}/lock` (E8) — owning IC, plan `DRAFT`, no body (optional `If-Match` version) → returns the updated `WeeklyPlanDto` (state `LOCKED`, `lockedAt` set, `managerReview` now present, `allowedActions` recomputed).
- [ ] **Authz first** — `authorizePlanAccess(principal, planId)` chokepoint; non-owner IC → codeless `404`+audit (a manager can READ a report's plan but **cannot lock it** — lock is IC-owner-only; see Step-2.5 Q1).
- [ ] **RULE #1 — required Supporting Outcome at lock (REQ-E-001, the demo's headline):** reject `DRAFT→LOCKED` unless **≥1 PLANNED commitment AND every PLANNED commitment links a Supporting Outcome**. Empty plan → **`409 EMPTY_PLAN_LOCK`**; any unlinked planned commitment → **`409 UNLINKED_PLANNED_COMMITMENT`** with **`fieldErrors[]` naming each unlinked commitment's `supportingOutcomeId`** (B.21 example). Reuse `canLock`'s predicate.
- [ ] **One `@Version`-guarded transaction** does ALL of: set `state=LOCKED` + `lockedAt`; insert `manager_review` (`NOT_REVIEWED`, `review_due_at` via `ReviewSlaService`); synchronous `manager_plan_summary` + `manager_heatmap_cell` upsert (§9 count derivation); insert `audit_event` (`PLAN_LOCKED`, actor=IC); insert `outlook_calendar_sync_record` (`event_kind=IC_PLANNING`, `related_type=WEEKLY_PLAN`, `status=PENDING_PUBLISH`); idempotently upsert the locking IC's **direct manager's** `MANAGER_REVIEW_BLOCK` record (`related_type=MANAGER_REVIEW_WEEK`, `owner_employee_id`=manager, `week_start_date`, partial-unique grain — first report's lock creates it, later locks are no-ops). A concurrent double-lock → `409` via `@Version`.
- [ ] **SLA `reviewDueAt` (Appendix F.3):** `ReviewSlaService` = **17:00 org tz on the next BUSINESS day** (weekdays-only) after `lockedAt`, from the injectable `Clock`. Friday lock → Monday 17:00. Pinned with `java.time.Clock` cases.
- [ ] **`isOverdue` is DERIVED, never stored** (rule #6) — `now > reviewDueAt ∧ status=NOT_REVIEWED`, computed at read time in `ReviewMapper` via the injectable `Clock` (`REVIEWED`/`REVIEWED_WITH_DISPUTES` ⇒ never overdue).
- [ ] **RULE #4 — Outlook sync NEVER blocks the lock (NEVER-TRIM):** the SNS publish (`PENDING_PUBLISH→QUEUED`) happens **AFTER** the core transaction commits; an SNS/publish failure is **caught + logged + leaves the sync record retained** (retryable) and **NEVER rolls back or fails the lock** (§3/§10/§16, Diagram 1). The SNS/SQS payload is **pointer-only** `{syncRecordId, eventKind, env, traceId}` — no secrets/PII (rule #7).
- [ ] **RULE #2 baseline immutability** — proven via an integration test: after a real lock, an E6 baseline-field edit → `409 LOCKED_BASELINE_EDIT` (the 3.4b gate firing on the locked state); `alignmentStatus` edit → `409 ILLEGAL_STATE_TRANSITION`.
- [ ] Transition logic lives in **`PlanLifecycleService`** (NOT the controller — forbidden-pattern #4); `./gradlew check` green; 100% line on new types.

## Things to flag at Step 2.5 (the fresh orch reviews these)
1. **Lock is IC-owner-only** (a manager-direct-report can READ via E4 but cannot lock). 2. **Transaction boundary + the post-commit SNS publish.** The SNS publish MUST be outside/after the `@Transactional` core (so a publish failure can't roll back the commit) — e.g. `TransactionSynchronization.afterCommit` or a service-level "commit then publish in a try/catch". Confirm the mechanism pins rule #4 (the test: stub the SNS publisher to throw → assert the plan is still `LOCKED` + the sync record retained).
3. **Reuse `canLock`'s predicate for the precondition** (don't duplicate) — confirm how `PlanLifecycleService` shares the exact predicate `AllowedActionResolver` emits (extract a shared predicate if needed). The `UNLINKED_PLANNED_COMMITMENT` `fieldErrors[]` must name each unlinked commitment.
4. **`MANAGER_REVIEW_BLOCK` idempotency + the no-manager case.** First direct-report lock creates the per-manager/week block; later locks are no-ops (partial-unique). ## LOCK-INVARIANT REVIEW CHECKLIST (for the fresh orchestrator's Step-2.5 + Step-9 scrutiny)
The successor orch MUST verify the impl's test plan pins ALL of:
- **Rule #1:** empty plan → `EMPTY_PLAN_LOCK`; one unlinked planned → `UNLINKED_PLANNED_COMMITMENT` + `fieldErrors[]` naming it; a fully-linked ≥1-planned plan → locks. (REQ-E-001 — the demo headline.)
- **Rule #2:** post-lock baseline edit → `409 LOCKED_BASELINE_EDIT` (3.4b gate on the real locked state); `alignmentStatus` → `409 ILLEGAL_STATE_TRANSITION`.
- **Rule #4:** SNS publish failure → plan STAYS `LOCKED`, sync record retained as retryable, NO rollback (the load-bearing non-blocking test — stub the publisher to throw). Payload pointer-only (rule #7).
- **Atomicity:** all core side-effects (state, review, projections, audit, sync record, review-block) commit in ONE txn; a failure in any rolls back ALL (except the post-commit SNS publish, which is outside).
- **SLA:** Friday lock → Monday 17:00 org tz (weekday-only, injectable Clock); `isOverdue` derived not stored (rule #6).
- **Authz:** non-owner → 404+audit; double-lock → 409 (`@Version`).
- **Single-source:** the precondition reuses `canLock`, not a second copy.
- **Security-reviewer dispatched** at Step 7→8; any critical finding escalates immediately.
