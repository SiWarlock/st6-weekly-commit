# /tdd brief — 3.3a Plan DTO contract + `GET /api/plans/current` (WeeklyPlanDto, IC self-read)

> Third Phase-3 backend slice; **first half of task 3.3** (split — see below). **Not safety-critical** (E3 is IC self-scoped, like `/me` — no per-resource authorizer call, no IDOR surface). It establishes the **`WeeklyPlanDto` + nested `WeeklyCommitmentDto` + `RcdoBreadcrumbDto`** contract (DTOs 3/4/5 across the boundary) + the **`AllowedActionResolver`** affordance layer that every plan-returning endpoint (E4/E8/E9/E10/E11) reuses.
>
> **3.3 is split:** `GET /api/plans/{id}` (E4) — the first per-resource `DomainAuthorizationService` IDOR consumer (rule #3) — is carved into **034 = 3.3b** (own commit + ad-hoc security-reviewer, per the "authorization/IDOR slices stand alone" pitfall). 3.3a builds the DTO+mapper+resolver+self-read that 3.3b then reuses for the by-id endpoint.

## Feature
`GET /api/plans/current` (E3, IC scope) returns the authenticated IC's own current-week `WeeklyPlanDto` — the full B.5 shape with nested `WeeklyCommitmentDto[]` (B.6), per-commitment `RcdoBreadcrumbDto`, convenience counts, `managerReview` (null while DRAFT), and an actor-computed `allowedActions[]` (B.1/F.4) — mapped from entities by a new `PlanMapper`, served self-scoped (no authorizer call).

## Things to flag at Step 2.5
1. **Dispute-field omission (the contract one).** `WeeklyCommitmentDto` **omits** `hasUnresolvedDispute` (and any `dispute`). Building it now is throwaway (no disputes exist pre-disputes-slice → a hardcoded-`false` stub or a premature disputes query, both replaced later). **My default vote: omit** — the disputes slice adds `dispute?: AlignmentDisputeDto` fresh (Option-A, user-approved) + reconciles B.6 + the frontend mirror, all at once (zero rework, one coordination point). Confirm — or, if you'd rather match B.6 exactly now, include `hasUnresolvedDispute:false` (and accept the 2-line swap later).
2. **E3 current-plan absence.** §5 phrases E3 as "returns/creates-view of own current-week plan." If no shell exists for the caller's current week, what? **My default vote: return the existing shell; if absent → `404 PLAN_NOT_FOUND`** (no create-on-GET — generation 3.2 owns shell creation; a GET must not mutate). Confirm vs auto-creating a shell on read (I'd avoid — it conflates the generation responsibility and breaks GET safety; if the spec truly wants on-demand creation, that's better as an explicit semantic, flag it).
3. **Breadcrumb resolution seam.** The breadcrumb needs RC→DO→SO labels from a `supportingOutcomeId`. Default: reuse `RcdoReadService.findSupportingOutcome(id)` (3.1) + walk to DO/RC for labels (add a small `RcdoReadService.resolveBreadcrumb(soId)` if the walk isn't clean). Confirm where the breadcrumb assembly lives (RcdoReadService vs PlanMapper) — keep RCDO knowledge in the RCDO service.
4. **allowedActions ↔ lock-precondition sharing (drift guard).** The `LOCK` affordance predicate (DRAFT ∧ owning IC ∧ ≥1 planned ∧ all planned linked) **must be the SAME logic 3.5's `PlanLifecycleService` enforces** — else the UI shows LOCK enabled while enforcement rejects (§15 affordance↔enforcement drift). Default: `AllowedActionResolver` houses the predicate now; **3.5 reuses it** (do NOT duplicate — flag at 3.5). Confirm the predicate's home so 3.5 consumes it.
