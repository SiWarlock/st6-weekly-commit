# /tdd brief — 4.4 `POST /api/commitments/{id}/carry-forward` (E12) — carry unfinished work into next week

> **Fourth Phase-4 slice — the most complex.** Carry-forward is the only path that sets `reconciliation_outcome=CARRIED_FORWARD` (4.1 rejects a direct PATCH→CARRIED_FORWARD `400`). It (a) sets the source commitment's outcome to `CARRIED_FORWARD`, (b) creates a linked successor in the **next** Monday–Sunday DRAFT plan (creating that shell **only if absent**), (c) is **idempotent per source** (re-invoke returns the same successor), and (d) keeps projections in lockstep. ## Feature
`POST /api/commitments/{id}/carry-forward` (E12, owning IC, parent plan `RECONCILING`, **no request body**) sets the source commitment's `reconciliation_outcome=CARRIED_FORWARD` and creates a linked successor `weekly_commitment` (`carry_forward_source_commitment_id = source.id`) in the next Mon–Sun plan — creating that next-week **DRAFT shell only if absent**. Idempotent per source: re-invoking returns the existing successor (no duplicate, no second shell). Returns the next-week `WeeklyCommitmentDto`.
