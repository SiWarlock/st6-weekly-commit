## Feature
`POST /api/disputes/{id}/resolve` (E19, the active direct manager of the disputed commitment's plan owner, dispute `OPEN`/`IC_RESPONDED`) sets the dispute `RESOLVED` + `resolvedAt`; if the parent review is in a reviewed state, re-derives it (`REVIEWED_WITH_DISPUTES → REVIEWED` when this was the last unresolved dispute). Returns the updated `AlignmentDisputeDto`. REQ-F-017.

## Things to flag at Step 2.5
1. **[CONTRACT] `resolutionNote` — body-less (my default).** B.8 names an E19 `ResolveDisputeRequest` with "no required body (optional `resolutionNote` string)", but **the `AlignmentDispute` entity has no `resolutionNote` field** (only `managerNote`/`icResponse`/`resolvedAt`) and B.8 the response DTO has none either. My default: **ship body-less** (no request DTO, the optional note unimplemented in MVP — a manager can use a comment, E20/E21, for resolution context). Adding `resolutionNote` would be an entity + migration + DTO + Appendix change, out of scope for the resolve slice. **Confirm body-less, or flag if you read the contract as requiring the field** (then it's a bigger slice + a cross-doc change I'd escalate). I'll add the §5/B.8 "unimplemented in MVP" note if we defer.
2. **[CORRECTNESS — crux] The review re-derivation must preserve `NOT_REVIEWED`.** `ReviewStatusDeriver.derive(planId)` is **unconditional** — it returns `REVIEWED`/`REVIEWED_WITH_DISPUTES` from the count, never `NOT_REVIEWED`. So applying it blindly would flip a `NOT_REVIEWED` plan to `REVIEWED` when its last dispute resolves — WRONG (the manager hasn't reviewed). **Guard in the resolve service:** re-derive ONLY when `review.status != NOT_REVIEWED` (mirror 5.3's "re-derive only if `REVIEWED`"). My default: `if (review.getStatus() != NOT_REVIEWED) review.setStatus(deriver.derive(planId));`. Confirm the guard + the test `resolve_onNotReviewedPlan_staysNotReviewed`.
3. **[SCOPE] No projection change on resolve.** §3's flow shows `unresolved_dispute_count--`, but the projection is deferred to Phase 6 (the command center reads + recomputes-from-source; the dispute slices don't touch `ProjectionService`, per the 5.3 decision). The **review status** IS re-derived (it's read via the plan DTO). Confirm the no-projection default (pinned by `resolve_doesNotTouchProjection`).
4. **[REUSE] `authorizeDisputeResolution` is built (line 199) but UNWIRED.** Verify it's correct (it is — IC→403, manager→ok, unrelated→404) and wire it as the resolve chokepoint (first service statement). Add the endpoint-level authz tests (it previously had no endpoint caller). Confirm it gains 100% coverage through the resolve endpoint (no tested-but-unwired residue).
