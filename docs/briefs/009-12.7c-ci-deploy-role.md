## Feature
Provision the GitHub Actions **OIDC identity provider**, a **CI deploy role** that runs the full §13 deploy (broad service policy) but is **hardened**: an **IAM permissions boundary** caps the role + any IAM it creates, the OIDC trust is **environment-scoped** (`repo:<owner>/<repo>:environment:production`, gated by a GitHub Environment with required reviewers — HITL/12.11 side), no long-lived keys; plus the **CI EKS access entry** (deferred from 12.2) so CI can `kubectl apply`.

## Things to flag at Step 2.5
1. **★Q1 — permissions-boundary design (THE safety core).** The defense-in-depth has two parts: (a) the `ci_boundary` policy caps the role's MAX effective permissions; (b) the deploy policy's `iam:CreateRole`/`PutRolePolicy`/`AttachRolePolicy` are conditioned with `iam:PermissionsBoundary = <ci_boundary ARN>` so any role CI creates is itself bounded (closes the escalation loop). **My default vote:** boundary = the enumerated WC deploy service set (same services as the deploy policy, `Resource:*`); + the create-role boundary-condition. **Spike it + send the EXACT boundary + deploy policy JSON** so I can audit (the security review, like 12.7b). Flag if a tighter boundary (e.g. denying `iam:DeleteRolePermissionsBoundary`, `iam:CreateUser`, `iam:CreateAccessKey`) is warranted — I lean toward adding those explicit denies.
2. **★Q2 — OIDC subject = `environment:production` (per the ruling).** `repo:${var.github_repo}:environment:production`, StringEquals (exact). Confirm. (NOT branch-scoped — the human chose the Environment-gated posture.)
3. **Q3 — thumbprint omitted.** aws 6.x auto-handles the GitHub IdP thumbprint (12.7b finding). Confirm validate stays clean without `thumbprint_list`.
4. **★Q4 — EKS access-entry policy.** `AmazonEKSClusterAdminPolicy`, cluster-scoped (CI applies cluster-wide manifests: namespace/SAs/SPC/deployments/ingress/jobs/external-dns). Confirm cluster-admin (the full-apply ruling needs it).
5. **Q5 — deploy-policy service set sufficiency.** Confirm the enumerated set covers the full §13 chain incl. external-dns's route53 (the CI role does `terraform apply` which creates the external-dns IRSA role too). Flag any missing service.
