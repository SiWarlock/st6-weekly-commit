# /tdd brief — 4.2 `POST /api/plans/{id}/start-reconciliation` (E9) — PlanLifecycleService LOCKED→RECONCILING

> **First slice of Phase 4** (post-lock IC reconciliation lifecycle) — the lead-directed critical-path default. The lifecycle ENTRY: it unblocks 4.1 (outcome PATCH), 4.3 (unplanned), 4.4 (carry-forward), 4.5 (close), all of which need a `RECONCILING` plan. **Heavy reuse of the 3.5 lock-transition pattern** (LESSONS §28) — a `@Version`-guarded `PlanLifecycleService` transition + a non-blocking `IC_RECONCILIATION` sync record. Standalone commit (touches rule #4 non-blocking sync, reused not new).

## Feature
`POST /api/plans/{id}/start-reconciliation` (E9, owning IC, plan `LOCKED`) transitions the plan `LOCKED→RECONCILING` in one `@Version`-guarded transaction — stamps `reconciliation_started_at`, synchronously refreshes the manager projection's `plan_state`, writes the IC-actor audit, creates an `IC_RECONCILIATION` Outlook sync record, then publishes the SNS pointer **after** commit (strictly non-blocking). Returns the updated `WeeklyPlanDto` (B.5) with `allowedActions[]` recomputed.
