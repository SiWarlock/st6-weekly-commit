## Feature
Provision the SPA delivery + secret-store layer: a **PRIVATE** S3 bucket (block-public-access on) for the Vite assets, a **CloudFront** distribution using **Origin Access Control (OAC, not legacy OAI)** with a bucket policy scoped to the distribution, an **SPA fallback** (403/404 → `/index.html` 200), and **four Secrets Manager secrets** (`db`, `auth0`, `graph`, `demo`). The custom domain + ACM cert are deferred to 12.7 (DNS validation needs the 12.7 Route53 zone) — 12.6 ships the distribution on the default CloudFront cert.

**S3 + CloudFront (`s3_cloudfront.tf`):**
- [ ] PRIVATE bucket: `aws_s3_bucket` + `aws_s3_bucket_public_access_block` with **all four** settings `true` (block public ACLs/policy, ignore public ACLs, restrict public buckets); no public ACL; no website config.
- [ ] `aws_cloudfront_origin_access_control` (OAC — `signing_behavior=always`, `signing_protocol=sigv4`, `origin_access_control_origin_type=s3`).

- [ ] Outputs: `s3_assets_bucket_name`, `cloudfront_distribution_id` (live; append-only LESSONS §3).

## Things to flag at Step 2.5
1. **★Q1 — secret-value population (SAFETY).** `db` value is TF-populated (Pattern 2, from 12.3). For `auth0`/`graph`/`demo` (real third-party creds): Options: (a) secret **container only** (`aws_secretsmanager_secret`, no version) — but the CSI mount / app expects a value to exist; (b) container + a **placeholder version** (`{}` or `"PLACEHOLDER"`) with `lifecycle { ignore_changes = [secret_string] }` so HITL populates the real value out-of-band without TF reverting it; (c) populate from sensitive TF variables. **My default vote: (b)** — keeps real 3rd-party secrets OUT of TF state/vars (rule #7) while giving the CSI mount a secret to bind. Confirm; flag if the ASCP/CSI mount needs a specific JSON shape even for the placeholder.
2. **★Q2 — CloudFront cert/alias deferral to 12.7.** 12.6 distribution uses `cloudfront_default_certificate = true` + no `aliases` (validates standalone; the us-east-1 ACM cert is DNS-validated against the 12.7 Route53 zone — can't reference it here, LESSONS §3). **12.7 will modify this distribution** to attach `viewer_certificate { acm_certificate_arn = <us-east-1 cert> }` + `aliases = ["wc.${ROOT_DOMAIN}"]`. **My default vote:** proceed with the default cert; surface the 12.6↔12.7 cert/alias split at Step 9 (I annotate the tracker, same as the 12.2↔12.7 access-entry split). Confirm — and confirm whether 12.7 attaches by editing s3_cloudfront.tf or via a parameterized aliases/cert var (your call which is cleaner).
3. **Q3 — bucket-policy ↔ distribution reference (no cycle).** The distribution references the bucket regional domain name (origin); the `aws_s3_bucket_policy` references the distribution ARN (SourceArn). Confirm this resolves without a cycle (standard OAC pattern — bucket policy depends on the distribution, distribution depends on the bucket as origin via its domain attribute, not the policy).
4. **Q4 — SPA fallback codes.** Both 403 AND 404 → `/index.html` 200 (S3+OAC returns 403 for missing keys when listing is denied; 404 for some paths). **My default vote:** map both. Confirm.
5. **Q5 — secret name uniqueness / naming.** Secrets Manager names must be unique; recommend `wc/${var.env}/db` etc. (or `wc-${var.env}-db`). **My default vote:** `wc/${var.env}/<name>` path-style. Flag if you prefer flat.
