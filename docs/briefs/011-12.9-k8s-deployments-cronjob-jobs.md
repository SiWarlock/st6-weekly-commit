## Feature
Author the five workload manifests that run on the 12.8 surface: `deployment-api` (wc-api behind the ALB), `deployment-worker` (wc-sync-worker), `cronjob-generation` (weekly plan-shell generation), the pre-deploy `job-migration` (the **sole** Flyway schema owner), and the opt-in `job-perf-seed` (REQ-D-008, never in the normal deploy chain). Each pod runs as its 12.8 ServiceAccount, mounts its per-SA SecretProviderClass at `/mnt/secrets` via the Secrets Store CSI volume, and carries the Appendix D env contract for its workload.

## Things to flag at Step 2.5
1. **★Q-image — how the image ref is injected.** The ECR repo URL is a 12.4 TF output and the tag is the commit SHA (§13), both known only at deploy. **My default vote:** a single `${ECR_API_IMAGE}` / `${ECR_WORKER_IMAGE}` placeholder per Deployment/Job (full `repo:tag`), bound by the 12.11 allowlisted `envsubst` (LESSONS §14) — consistent with the 12.8 token pattern. Add the new tokens to the documented envsubst allowlist. Confirm.
2. **★Q-csi — CSI secret volume wiring.** Each pod mounts its per-SA 12.8 SecretProviderClass as a `secrets-store.csi.k8s.io` volume (`readOnly: true`, `volumeAttributes.secretProviderClass: <wc-…-spc>`) at `/mnt/secrets`. **My default vote:** one CSI volume per pod referencing that workload's SPC by name; mount readOnly at `/mnt/secrets`; the DB/Auth0/Graph **secret values are files (NOT env)** — only non-secret config is plain `env:`. Confirm the SPC names match 12.8 and the mount path = `/mnt/secrets`.
3. **★Q-probes — actuator probes ahead of the backend impl.** The `/actuator/health/{liveness,readiness}` endpoints are implemented in **13.3** (backend, st6-main). **My default vote:** declare the probes now (the manifest is the contract; 13.3 fulfills it; probes are inert until the image ships them + deploy). They validate fine in kubeconform. Note the forward-dependency at Step 9. Confirm OK to declare ahead.
4. **Q-resources — requests/limits under the thin posture.** **My default vote:** modest explicit `resources.requests` (cpu/mem) + `limits` per container so the single node group schedules predictably (RISK-009 thin, but requests prevent overcommit). Confirm values or omit-for-MVP.
5. **Q-perf-sa — perf-seed ServiceAccount.** perf-seed writes synthetic data to the DB (db secret only). **My default vote:** reuse `wc-migration` (db-only IRSA, already least-privilege for a DB-writing one-shot) rather than mint a new SA/IRSA (out of 12.8 scope). Confirm — flag if you'd rather a dedicated SA (would need a 12.7b/12.8 re-touch — avoid).
6. **Q-ordering — migration-before-deploy.** §12 requires the migration Job to complete before the Deployments/CronJob roll. **My default vote:** the manifest itself only declares the one-shot Job (`restartPolicy: Never` + `backoffLimit`); the **ordering is enforced by the 12.11 pipeline** (`kubectl wait --for=condition=complete job/...` gate), NOT by k8s. Confirm this slice stops at the Job manifest; the wait-gate is 12.11's.
