## The 12 tables (per §4 / Appendix A)
`employee`, `manager_relationship`, `rally_cry`, `defining_objective`, `supporting_outcome`, `weekly_plan`, `weekly_commitment`, `manager_review`, `alignment_dispute`, `comment`, `outlook_calendar_sync_record`, `audit_event`. All domain tables carry the `AbstractAuditingEntity` columns (created_by/at, updated_by/at).

## The 4 contract deltas (encode verbatim — these are pins)
1. **`weekly_commitment.manager_alignment_note text null`** is PRESENT (NEW).
2. **`weekly_commitment.progress_status` is ABSENT** (dropped — redundant with `reconciliation_outcome` + `outcome_note`).
3. **`comment`** keeps `parent_comment_id` / `path` / `depth` columns but flat MVP: `parent_comment_id` nullable, `path` nullable, `depth default 0`; `target_type` `CHECK IN ('PLAN','COMMITMENT')` only.
4. **`outlook_calendar_sync_record.week_start_date date null`** (NEW); `related_type` `CHECK` includes `MANAGER_REVIEW_WEEK` (not `MANAGER_REVIEW`).

- [ ] Every status/enum column is `VARCHAR` + `CHECK` over the **exact** 0.3 enum value set: `weekly_plan.state` (4), `weekly_commitment.commitment_kind/priority/work_type/confidence/alignment_status/reconciliation_outcome`, `manager_review.status` (3 — **no `OVERDUE`**), `alignment_dispute.status/flag_type`, `comment.target_type` (`PLAN`/`COMMITMENT` only), `outlook_calendar_sync_record.related_type`(`WEEKLY_PLAN`/`MANAGER_REVIEW_WEEK`)/`event_kind`/`status` (6), `employee.role` (`IC`/`MANAGER`).
- [ ] The 4 contract deltas hold (manager_alignment_note present; progress_status absent; comment flat-but-nestable; sync week_start_date + MANAGER_REVIEW_WEEK).
- [ ] `@Version` integer column on `weekly_plan`, `weekly_commitment`, `manager_review`, `alignment_dispute`, `outlook_calendar_sync_record`.
- [ ] FKs per Appendix A (relationship→employee ×2, DO→rally_cry, SO→DO, plan→employee, commitment→plan, commitment.supporting_outcome_id→SO nullable, commitment.carry_forward_source_commitment_id→self nullable, review→plan+employee, dispute→commitment+employee, comment.author→employee + nullable parent→comment, sync.owner→employee, audit.actor_employee_id→employee **nullable** for SYSTEM).

## RED test outline (Step 2) — Testcontainers PG (never H2)
1. **`v1_migrates_clean_all_tables`** — Flyway V1 applies on Testcontainers PG16; assert all 12 tables + key columns exist (JDBC metadata).
2. **`check_constraints_reject_out_of_vocab`** — inserting `weekly_plan.state='ARCHIVED'`, `comment.target_type='MANAGER_REVIEW'`, `manager_review.status='OVERDUE'`, `sync.related_type='MANAGER_REVIEW'` each raises a `CHECK` violation.
3. **`contract_deltas`** — `weekly_commitment` has `manager_alignment_note`, has NO `progress_status`; `comment` columns flat (depth default 0, parent nullable); `sync` has `week_start_date` + accepts `related_type='MANAGER_REVIEW_WEEK'`.
4. **`unique_and_fk_violations`** — duplicate `(employee_id, week_start_date)` raises unique violation; a commitment with a non-existent `supporting_outcome_id` raises FK violation; `manager_relationship` with manager==report raises the `CHECK`.
5. **`system_actor_null_insert`** (integration) — a row with `actor_employee_id` NULL inserts into `audit_event` (SYSTEM actor path).
6. **`enum_check_matches_enum_values`** — for each status column, assert the `CHECK` allowed-set equals the corresponding 0.3 `enum.values()` (extends LESSONS §3 to the DB layer — pins enum↔CHECK alignment so they can't silently diverge).
