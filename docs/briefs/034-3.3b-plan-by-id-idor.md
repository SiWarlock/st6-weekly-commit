## Feature
`GET /api/plans/{id}` (E4) returns the `WeeklyPlanDto` (B.5) for an **authorized** actor — IC reads own plan, Manager reads a direct-report's plan — by calling `DomainAuthorizationService.authorizePlanAccess(principal, planId)` **before** any data is exposed; any other actor (or a non-existent id) → **`404` (IDOR-safe, codeless, never reveal existence)**, with a `REQUIRES_NEW` denial `audit_event` on a *genuine* denial. Reuses 3.3a's `PlanMapper`/DTOs.

## Acceptance criteria (what "done" means)
- [ ] `GET /api/plans/{id}` calls **`authorizePlanAccess(principal, planId)` BEFORE** loading/mapping the plan for the response (the authorizer is the chokepoint — no plan data is read into a response path before authorization).
- [ ] **IC reads own plan → 200** `WeeklyPlanDto` (reuses 3.3a's mapper, same B.5 shape + `allowedActions[]`).
- [ ] **Manager reads an active-direct-report's plan → 200**.
- [ ] **Cross-IC** (IC reads another IC's plan) → **`404`** (codeless `ResourceNotFoundOrUnauthorized`, never reveal existence) **+ one `REQUIRES_NEW` denial `audit_event`** (safe metadata, no PII).
- [ ] **Non-direct-report manager** (manager reads a non-report's plan) → **`404` + denial audit**.
- [ ] **Genuinely-missing id** (no such plan) → **`404` (SAME codeless body) but NO audit** (genuinely-missing ≠ denial — LESSONS §17). The response is **indistinguishable** from the cross-owner 404 (that's the IDOR-safety point); only the server-internal audit differs.
- [ ] **Unauthenticated → 401** (composes the 2.6 chain).
- [ ] `./gradlew check` (from `apps/wc-api/`) green; 100% on the new E4 path.

## Things to flag at Step 2.5
1. **Authz placement — service, not controller.** Default: `authorizePlanAccess` is called **first thing in `PlanService.getPlanById`**, before any plan load reaches a response path (controllers stay coarse/thin per the 2.5 pattern — the authorizer is the service-layer chokepoint, rule #3). Confirm (vs a controller-level call — don't).
2. **The two 404 flavors.** Genuinely-missing id → 404 **no audit**; existing-but-unauthorized → 404 **+ denial audit** — but **both render the identical codeless body** (`ResourceNotFoundOrUnauthorized`, no `code`) so existence is never revealed. Confirm the existing `authorizePlanAccess`/`authorizeOwnership` already makes this distinction (it was built+tested at 2.5 — LESSONS §17); 3.3b's matrix just proves it end-to-end. If the distinction is NOT already correct in 2.5's code, **flag it** (that's a rule-#3 finding).
3. **E4's 404 is the codeless IDOR 404, NOT 3.3a's `PLAN_NOT_FOUND`.** E3 (self-scoped) returns the named/coded `PLAN_NOT_FOUND` for your own absent shell; E4 (per-resource) must return the **codeless** `ResourceNotFoundOrUnauthorized` 404 (a named code on E4 would leak existence). Confirm the by-id path does NOT route through `PlanNotFoundException`.
4. **Reuse, don't re-map.** `getPlanById` reuses 3.3a's `PlanMapper` + `AllowedActionResolver` verbatim (same `WeeklyPlanDto`); the only delta from E3 is "authorize a given id" vs "resolve my current". Confirm no mapper changes.
