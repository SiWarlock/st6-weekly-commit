## Things to flag at Step 2.5
1. **[POSTURE — the one real design call] No audit on the DRAFT-state 409.** My default: a manager mark-reviewed/open-dispute on a DRAFT *direct-report* plan is a **state-precondition failure** (`409`), not an authorization denial — the manager IS authorized (they're the active direct manager), the plan simply isn't locked yet. Per the §15/§17/§25 audit philosophy (audit genuine denials — IDOR `404`, capability `403` — not routine workflow-state errors), it should **NOT** write an `audit_event`. The genuine denial (non-direct-report → `404`) DOES audit (existing). **Confirm this posture, or flag if you read REQ-F-010 / the MVP_TASKS line as requiring the state-409 to audit** (then it's a small production change + I escalate the audit-posture question). I lean strongly to no-audit (over-auditing state errors pollutes the security trail).
